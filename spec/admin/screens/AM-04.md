## 1. ID and name

- **ID:** AM-04
- **Name:** تغيير صيغة رقم الغرفة / Change room number format
- **Type:** Modal, no URL. Opens on top of A-07 only. **It cannot be dismissed by a backdrop click, by Esc, or by browser back**; it closes only through its own two buttons (`admin-map` §3.3 rule 5; A-07 §5.4.4 layer 2). It does not change the active sidebar item.
- **Language:** the dashboard language. Room numbers typed or listed here are shown exactly as typed or stored and are never translated.

---

## 2. Purpose

Save a new room-number format only after the manager has seen what it changes for guests and has proved, with a real room number from this hotel, that the new rule accepts it.

## 3. Entry and exit points

### 3.1 Entry

AM-04 opens when, and only when, **all** of these hold (A-07 §3.2):

1. The manager clicked A-07 `B01` "حفظ / Save";
2. A-07 `F01`–`F05` passed validation (A-07 §7);
3. A-07 `F06` holds a format different from the saved one, compared as stored values (§5.5).

Nothing has been sent when AM-04 opens. On open:

- the test field `F01` is **empty** — never pre-filled, never remembered from an earlier opening;
- keyboard focus is in `F01`;
- "تأكيد التغيير / Confirm change" (`B02`) is disabled;
- the history check of §5.2 starts at once.

AM-04 cannot open in build variant (b) of A-07 §6.5: there the format cannot change, so A-07 `B01` never finds it different. It cannot open from AM-01 either: AM-01's "حفظ ومتابعة / Save and continue" is disabled while the format differs (AM-01 §5.3), and AM-01 never opens on top of AM-04 (AM-01 §5.4).

## 5. Content

### 5.1 Layout, the from / to block, and the consequence text

Top to bottom: `C01` title · `C02` from / to · `C03` consequences · `C13` when shown · `S03` history check · `S04` live test · `C11` when shown · the button row, `B01` "إلغاء / Cancel" at the start edge and `B02` "تأكيد التغيير / Confirm change" at the end edge.

**Direction of the change.** Only two formats exist (§5.5), so a change is always one of two:

- **Tightening** — to `أرقام فقط / Digits only`. This is the direction that can lock out real rooms, and the one the live test exists for.
- **Loosening** — to `أرقام وحروف / Digits and letters`. Every value Digits only accepts (1–5 digits) is also accepted by Digits and letters (1–6 characters of which digits are allowed), so loosening can never refuse a room that is accepted today.

**`C02` — names and rule summaries.** Each summary states exactly what the stored rule does (§5.5), no more and no less:

### 5.2 The history check (`S03`)

AM-04 checks the room numbers the hotel has already received against the **new** format and reports how many it would refuse. **It informs; it never blocks** (A-07 §5.4.4 layer 4): a stored room number may be a guest's own typing mistake, and refusing a change because of a typo would make the setting impossible to tighten.

| Rule | Value |
|---|---|
| Source | Every stored order within the 365-day retention of A-06 §7.5, **in every status**, Cancelled included — a cancelled order's room was still typed by a guest at this hotel |
| Distinct values | Room numbers compared after trimming and **without regard to letter case** (A-06 §7.3): `12b` and `12B` are one value. The spelling shown is the one on the most recent order |
| Test applied | The live test's rule of §5.3, for the new format, to each distinct value |
| Result | `N` = the number of distinct values the new format refuses; `M` = the number of distinct values checked |
| Examples in `C06` | Up to **5** refused values, the most recently ordered first, separated by `، ` in Arabic and `, ` in English |
| When | Once, when AM-04 opens. It is not re-run while AM-04 stays open |
| Timeout | **10 seconds**, then the failure copy of §7.3.1 |
| Effect on `B02` | `B02` stays disabled **while the check is in progress**, so its result is on screen before anything can be saved. **Its result, whatever it is — including a failure — never disables `B02`** |

Under tightening, a hotel that has received orders from rooms such as `A-12` sees them listed here, on its own data, next to the test field; `C07` asks the manager to test one of them. Under loosening the check normally finds nothing to refuse (§5.1, "Direction"), and says so.

### 5.3 The live test (`S04`) — what it checks

This is the protection. `B02` "تأكيد التغيير / Confirm change" can be clicked **only while a room number typed by the manager is accepted by the new format**, evaluated by the rule the guest's G-04 will run once the format is saved.

**`C09` — the instruction, exact copy by direction.** It points the test at the case the change is about:

| Direction | Arabic | English |
|---|---|---|
| Tightening | اكتب رقم غرفة حقيقيًا من فندقك كما هو مكتوب على الباب. إن كان في فندقك رقم غرفة فيه حرف أو شرطة فاختبره هو، وإلا فاختبر أطول رقم غرفة لديك. | Type a real room number from your hotel exactly as it appears on the door. If any room at your hotel has a letter or a hyphen, test that one; otherwise test your longest room number. |
| Loosening | اكتب رقم غرفة حقيقيًا من فندقك كما هو مكتوب على الباب، ويُفضَّل رقم فيه حرف أو شرطة، فهو سبب هذا التغيير. | Type a real room number from your hotel exactly as it appears on the door — preferably one with a letter or a hyphen, since that is why you are making this change. |

**What the test checks, step by step** (full rules in §7.1 and §7.2):

1. **The value.** What the manager typed in `F01`, with Arabic-Indic and Extended Arabic-Indic digits converted to `0–9` as they are typed (visible in the field, as in G-04 §7.1), then trimmed of leading and trailing spaces. This is exactly the value the guest's G-04 would send (A-07 §7.7).
2. **The rule.** The **new** format's stored value (§5.5), turned into a rule by **the same construction `roomRule()` in `/shared/hotel-db.js` uses** — the same character class, the same separator placement, the same length bounds — applied to the candidate value instead of the saved one. It must be that construction itself, not a second copy written for AM-04: the test protects the hotel only as far as it is the rule the guest will run. (Flag: `roomRule()` today reads only the saved settings and takes no candidate; §9 decision 5.)
3. **The checks, in this order**, stopping at the first that fails:
   - a. **Empty** after trimming → no verdict; `C10` shows the prompt copy; `B02` disabled.
   - b. **Characters** — every character must be a digit, a Latin letter when the format allows letters, or the format's separator when it has one → otherwise **Refused**, reason *wrong characters*.
   - c. **Length** — at most the format's maximum (5 or 6), counted on the whole trimmed value, separators included → otherwise **Refused**, reason *too long*.
   - d. **Structure** — the separator is never first, never last, never next to another separator (the `roomRule()` pattern) → otherwise **Refused**, reason *structure*. Reachable only under Digits and letters, the only format with a separator.
   - e. **Minimum length** — at least the format's minimum. Both presets have minimum 1, so after check (a) this never fails; it is listed because it is part of `roomRule()`.
   - f. All passed → **Accepted**.
4. **The verdict** is shown in `C10` on every change of `F01`, with no request and no delay. A **Refused** verdict prints the exact message the guest would see under the field on G-04 for that value (§5.6), in the dashboard's language, so the manager reads the guest's failure, not a technical one.

Accept or refuse is decided by exactly the checks `roomRule()` performs; splitting its single character-and-separator pattern into checks (b) and (d) changes only which message is shown, never the verdict.

| `A 12` | Refused — wrong characters | Refused — wrong characters (a space is not a separator in the stored format; §9 decision 3) |

### 5.4 What blocks saving, and what "تأكيد التغيير / Confirm change" does

**`B02` is disabled** exactly while one of these holds, and `C10` or `C05` always states which:

| Condition | Where the reason is on screen |
|---|---|
| `F01` is empty after trimming | `C10` prompt copy |
| The test value is **Refused** by the new format | `C10` refused copy, with the guest's message |
| The history check is in progress (at most 10 seconds) | `C05` "جارٍ فحص… / Checking…" copy |
| A save is in flight | `B02` reads `C12` "جارٍ الحفظ… / Saving…" |

Nothing else disables it: not the history check's result, not a failed history check, not the number of refused room numbers.

**On a click on `B02`**, in this order:

1. **In-flight, synchronously on the click**: `B02` shows `C12`; `F01` and `B01` are disabled; a second click does nothing.
2. **Re-check.** The test value is evaluated again, by §5.3, against the exact format value about to be written. If it is refused, **nothing is written**, AM-04 stays open, `C10` shows the refused copy and `C11` the "not saved" copy of §7.3.3. This is layer 5 of A-07 §5.4.4 ("the server re-checks"); in this build the store has no server (`/shared/CONTRACT.md`), so the re-check is the last step before the write, in the same action (§9 decision 6).
3. **One write of the whole settings record** (A-07 §5.5), through the data layer's settings save (`saveSettings`): both hotel names and both currency labels trimmed, the time zone, the new format's stored value (§5.5), and the **audit record** — the moment of this save and the signed-in account's email — so A-07 `C14` can print it (§9 decision 7). The test value is **not** stored.
4. **Success** means both: the write reports success, **and** a fresh read of the settings returns the new format's stored value exactly. Anything else — the write reports failure, the read returns another value, or 10 seconds pass — is a failed save (§6.3 case 2).
5. On success, AM-04 closes within 100 ms and A-07 shows the success state of A-07 §6.4.

### 5.5 The two formats as stored values

The format is stored as the `roomFormat` value of the settings record, in the shape `/shared/hotel-db.js` defines: `{ minLen, maxLen, allowLetters, separator }`. The dashboard writes **exactly one of two values** and never any other (A-07 §5.4.1: "no third option, no free text, no editable length"):

| Preset (A-07 `F06`) | Stored `roomFormat` | Relation to the guest spec |
|---|---|---|
| 1 — أرقام فقط / Digits only | `minLen 1, maxLen 5, allowLetters false, separator ''` — equal, field for field, to the data layer's `DEFAULT_ROOM_FORMAT` | Exactly G-04 §7.1 as approved. `roomRule()` reports it as the default, and the guest keeps G-04's three reviewed messages |
| 2 — أرقام وحروف / Digits and letters | `minLen 1, maxLen 6, allowLetters true, separator '-'` | OQ-01's proposed alternative as far as the stored shape can express it; two differences are recorded in §9 decision 3 |

- The data layer's shape can express more than these two values (a maximum up to 12, the separators `/` and `.`). **The dashboard offers none of that and writes none of it.**
- "Different from the saved format" (§3.1) compares the saved value, after the data layer's own normalisation, with the preset's value above, field by field.
- **A saved value that equals neither preset** can exist only if storage was written outside the dashboard. AM-04 then shows `صيغة غير معروفة / Unrecognised format` in the "current" row of `C02`, treats the change as tightening when the target is Preset 1 and as loosening when it is Preset 2, and runs the history check and the test exactly as for any change. Saving writes a preset value, so the unrecognised value is replaced. How A-07 `F06` displays such a value is not defined by A-07; §9 decision 8 flags it.

### 5.7 What AM-04 never does

- It never saves anything by being opened, left open, or cancelled.
- It never closes on a backdrop click, on Esc, or on browser back.
- It never pre-fills or remembers the test value, and never stores it.
- It never lets the history check block a save, and never lets a refused test value be saved.
- It never offers a third format, a length, a separator or a pattern to edit (A-07 §5.4.1).
- It never changes a submitted order or a stored room number.
- It never opens AM-01, and AM-01 never opens on top of it.

## 6. States

### 6.1 Loading

- **History check in progress** (on open): `C05` reads "جارٍ فحص أرقام الغرف في الطلبات السابقة… / Checking room numbers in past orders…"; `C06` and `C07` hidden; `F01` usable and `C10` live; `B02` disabled. Timeout **10 seconds**, then §6.3 case 1.
- **Save in flight** (A-07 §6.1 refers here): entered synchronously on the click on `B02`. `B02` reads `C12` "جارٍ الحفظ… / Saving…" and ignores clicks; `F01` and `B01` disabled; the backdrop, Esc and browser back still do nothing. Timeout **10 seconds** (A-07 §6.1), then §6.3 case 2. No spinner, no countdown.

### 6.2 Empty

- **No past orders** in the retention window: `C05` "لا توجد طلبات سابقة لفحصها. / There are no past orders to check."; `C06`, `C07` hidden. The test still applies; `B02` is enabled once the test value is accepted.
- **Test field empty** (the state on open): `C10` shows the prompt copy; `B02` disabled.

### 6.3 Error

1. **The history check failed or timed out**: `C05` shows the failure copy of §7.3.1. `C06`, `C07` hidden. `B02` is no longer held by the check. There is no retry button: the check informs only, and the test is the protection.
2. **The save failed, timed out after 10 seconds, or the read-back did not return the new format**: AM-04 stays open; `C11` shows "تعذّر الحفظ — تحقّق من الاتصال وحاول مرة أخرى. لم يُفقد ما كتبته. / Could not save — check your connection and try again. Nothing you typed was lost."; `F01` keeps the test value; `B01` and `B02` usable again. Nothing on A-07 changes.
3. **The re-check refused the test value** (§5.4 step 2): AM-04 stays open; `C10` shows the refused copy; `C11` shows "لم يُحفظ التغيير: الصيغة الجديدة لا تقبل رقم الاختبار. / The change was not saved: the new format refuses the test room number."; `B02` disabled until the value is accepted.
4. **The test value is refused while typing** is not an error state of the modal: it is the test working. `C10` shows it; `B02` stays disabled.
5. **Expired session**: A-01 per `admin-map` §4.3, with `A-01-C04`; nothing was saved.

### 6.4 Success

The save succeeded (§5.4 step 4): AM-04 closes within 100 ms; A-07 shows the saved values, "تم حفظ الإعدادات / Settings saved" for 5 seconds, and the audit line "آخر تغيير: {DD/MM/YYYY HH:MM} — {account email} / Last changed: {DD/MM/YYYY HH:MM} — {account email}" with this save's time in the hotel time zone as saved and the signed-in account's email.

## 9. Decisions settled on this screen

1. **The live test is the gate.** "تأكيد التغيير / Confirm change" is enabled only while a room number the manager typed is accepted by the new format, evaluated by the guest's own rule construction; the verdict quotes the guest's own error message. The history check informs and never gates, as A-07 §5.4.4 promises; the only way it touches the button is by holding it for at most 10 seconds so its result is read first.

2. **Promises from A-07 kept, one by one.** Closes only through its two buttons (A-07 layer 2); Cancel reverts only the format and keeps other edits (A-07 §3.1); Confirm saves every edited setting in one write (A-07 §5.5); the test value is the guest's value, trimmed and converted (A-07 §7.7); a save refused on re-check changes nothing (A-07 AC 18); the audit line is written in the same step (A-07 layer 5, `C14`); the in-flight state is inside AM-04 (A-07 §6.1); the history check is in §5.2 and the test in §5.3, where A-07 points.

3. **Specified against the real `roomFormat` shape — recorded disagreement with A-07 and the map.** `/shared/hotel-db.js` stores `{ minLen, maxLen, allowLetters, separator }`, where `separator` is **one** of `-`, `/`, `.`, and there is no "at least one digit" rule. A-07 §5.4.1, A-07 `F06` option 2's helper line ("a hyphen or a single space"), A-07 acceptance criterion 22, and `admin-map` §5.5 rule 1 describe Preset 2 as OQ-01's alternative, which also accepts **a single space** as a separator and **requires at least one digit**. The stored shape can express neither. AM-04 stores Preset 2 as `{1, 6, true, '-'}` and its test and summaries state what that value does, because the test is only a protection if it runs the rule the guest will run. Effects: `A 12` is **refused** (A-07 AC 22 says accepted); `ABC` is **accepted** (A-07 AC 22 says refused). A hotel whose doors read `A 12` is therefore stopped by AM-04's own test before anything is saved — the protection covers this gap too. **Owner decision needed, one of:** (a) amend A-07 §5.4.1, the `F06` helper line and AC 22 to "hyphen only, no digit requirement", matching the data layer — the smaller change; or (b) extend the stored shape to allow a space separator and an at-least-one-digit rule, after which AM-04's summaries and examples change and nothing else in this file does. A-07, the map and the data layer were not edited.

4. **The guest copy under Preset 2 is ruled here.** `roomRule()` marks its `messages` as "PROVISIONAL copy until the admin spec (A-07 / AM-04) rules it". The ruling: under the default rule the guest shows G-04 §7.1's three messages unchanged; under Preset 2 the guest shows the four messages of §5.6, OQ-01's strings verbatim. Against the provisional copy: `long` for a maximum of 6 is already identical to OQ-01's; `chars` is replaced; a **structure** message is added, chosen when every character is allowed but the separator is misplaced; `short` is never reachable. Recorded for the owner to route to the data layer and the guest build.

5. **Two data-layer requirements, recorded, not made.** (a) The test must run `roomRule()`'s construction on a **candidate** format; today `roomRule()` takes no argument and reads only the saved settings, so that construction has to become callable with a candidate format. (b) `roomRule()` reads the saved settings on **every** call ("every read reloads from storage"), so a guest tab calling it at validation time would pick up a format change mid-checkout — contrary to A-07 §5.4.3 point 3 and `admin-map` §5.3 and §5.5 rule 5 ("never mid-session"). The guest build must read the rule once when the tab loads the store and keep it for the life of the tab. Neither `/shared/hotel-db.js` nor any guest file was edited.

6. **No server: the re-check and the read-back live in the save step.** A-07 §5.4.4 layer 5 and A-07 AC 18 speak of a server that refuses a format change without a passing test value. `/shared/CONTRACT.md` states there is no backend, and the data layer's settings save performs no check. The re-check is therefore the last step before the write, in the same action (§5.4 step 2), and success is confirmed by reading the stored format back (§5.4 step 4). The protection A-07 describes is kept; only its location moves, and this is recorded as a difference from A-07's wording.

7. **The audit record is not in the documented settings shape — flag.** A-07 `C14` needs the moment of the last format change and the account that made it. The settings shape in `/shared/hotel-db.js` and `/shared/CONTRACT.md` lists no such fields (the data layer's settings save does keep any extra value it is given). AM-04 writes both in the same settings write as the format. **Proposed for the owner:** add them to the documented settings shape under the names `roomFormatChangedAt` (ms) and `roomFormatChangedBy` (account email), so A-07 and any later reader rely on a contract rather than on an undocumented extra.

8. **A stored format that equals neither preset** is shown as `صيغة غير معروفة / Unrecognised format` here and is replaced by the next save. **Flag:** A-07 §7.4 says exactly one of the two options is always selected but does not say which one A-07 `F06` shows for such a value; A-07 was not edited.

9. **The test field is empty on every opening, is never stored, and Enter does not save.** A remembered value would let a second format change pass on the first change's evidence; a keyboard Enter after typing the room would turn the test into the confirmation.

10. **The instruction line points the test at the dangerous case** — a room with a letter or hyphen, else the longest room — because a manager tightening the format who tests `305` proves nothing. Nothing can verify that the typed room is real; the instruction, the history check and the consequence line 1T are the version-1 answer, and a room list remains backlog G-04-L5.
