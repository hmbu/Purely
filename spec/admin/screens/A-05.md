## 1. ID and name

- **ID:** A-05
- **Name:** الفئات / Categories
- **Type:** Full admin screen inside the global frame. The only place where a category is created, renamed, reordered or deleted.
- **Language:** the dashboard language for labels and buttons. Category names are shown and edited in **both** languages on every row, whichever language the dashboard is in (`admin-map` §4.2).

---

## 2. Purpose

Set the categories the guest's sticky category bar shows, what each is called in both languages, and the order the guest meets them in.

## 3. Entry and exit points

### 3.1 Entry

| From | Trigger | What A-05 shows |

### 3.2 Exit

| Action | Destination |
|---|---|
| `B01` "+ فئة جديدة / New category" | Stays on A-05; the inline row `S03` opens at the end of the list in add mode |
| `B04` "تعديل الاسم / Rename" on a row | Stays on A-05; that row is replaced by `S03` in rename mode |
| `B06` "حفظ / Save" in the inline row, both names valid | Stays on A-05; the row is saved, `S03` closes, `C05` confirms |

| `B05` "حذف / Delete" on an empty category | AM-02 variant C for that category; A-05 stays behind it |
| Any sidebar item, `AF-B07` sign out, or browser back — **with an inline row holding an unsaved edit** (§7.6) | AM-01 |
| Any sidebar item, `AF-B07`, or browser back — with no inline row open, or one with no unsaved edit | That destination, immediately |

## 5. Content

### 5.1 What the manager is looking at

The list is the guest's category bar, written out as rows: row 1 is the first chip a guest sees on G-01, row 2 the second, and so on (G-01 §5.3: "chips in the catalog's order … the guest interface never re-sorts"). A category that holds no active product is in the list but carries "مخفية / Hidden" in its store column, because it will produce no chip and no section for the guest (G-01 §5.3: "Empty categories have neither").

### 5.2 A category row (`C08`), start edge to end edge

| Column | Width | Contents |
|---|---|---|
| # | 48 px | The row's position, 1 to 20, Western digits. It is the chip position on G-01 **counting hidden categories**, so it is renumbered after every move |
| Arabic name | flexible | The saved Arabic name, 15 px, one line, never truncated (24 characters fit at 1024 px) |
| English name | flexible | The saved English name, 15 px, one line, never truncated |
| Products | 140 px | `{A}` = active products in this category (in stock and out of stock), 15 px. When removed products also sit in it: `{A}` followed by `+ {R} مُزال` / `+ {R} removed` at 13 px gray. Example: `4 + 1 مُزال` / `4 + 1 removed` |
| In the store | 160 px | `ظاهرة` / `Shown` when `{A}` ≥ 1; `مخفية — بلا منتجات` / `Hidden — no products` when `{A}` = 0. Plain text, 13 px, no icon, no color |
| Order | 80 px | `B02` ↑ and `B03` ↓ |
| Actions | 180 px | `B04` "تعديل الاسم / Rename" and `B05` "حذف / Delete" |

A category is "Shown" when it holds at least one **active** product, whether that product is in stock or not: G-01 renders out-of-stock cards with their badge (G-01 §5.4), so a category whose products are all out of stock still has a chip. A category holding only removed products is "Hidden", because removed products are not in the guest's catalog at all (A-03 §5.4).

### 5.3 Ordering

- `B02`/`B03` move one category exactly one place. The move is applied on screen within 100 ms, the `#` column is renumbered, and the order is saved immediately (`admin-map` §5.4). On failure the row moves back and `C06` appears.
- A new category is appended **last**.
- A rename never changes a position.
- Deleting a category closes its gap; every later row moves up one place.
- There is no drag-and-drop, for the reason A-03 decision 2 gives: ↑/↓ are precise, keyboard-usable and testable.
- The order includes hidden categories. A hidden category keeps its place, so when its first product is added it appears in the guest's bar exactly where this list shows it.

### 5.4 When a category can be deleted

A category can be deleted **only when it holds zero products, counting removed products**. `B05` is disabled otherwise, and `C11` states the rule and the remedy under the table.

Removed products count because a removed product can be restored (A-03 §5.4), and a restored product must land in a category that still exists. Counting them is what keeps A-03's "بلا فئة / No category" filter option (A-03 §7.2) a safety net that is never reached: under this rule no product ever loses its category, so A-04 decision 15 ("a product cannot exist without a category") holds for removed products too.

To empty a category, the manager opens each of its products on A-04 and chooses another category there. A-05 has no "move all products" action (§5.7).

Deletion is permanent. A category has no history of its own — orders record products, not categories (G-04 §7.8) — so nothing in A-02, A-06 or AM-03 ever needs a deleted category's name.

### 5.5 The inline row (`S03`)

- **Add mode** (`B01`): `S03` appears after the last row with both fields empty, focus in `F01`. `B06` saves a new category at the end of the order.
- **Rename mode** (`B04`): `S03` takes the renamed row's place with both saved names filled in. `B06` saves the new names; the category keeps its position, its products and its identity.
- One inline row at a time. While it is open, `B01`, every `B02`/`B03`/`B04`/`B05` are disabled, so the list cannot change under a half-typed name.
- `B07` "إلغاء / Cancel" and Esc discard the row's typed values **with no modal**. AM-01 guards *leaving the screen*; `B07` does not leave the screen, and its only purpose is to discard two short fields, so asking "discard?" after the manager has clicked "discard" would be the same question twice.
- Leaving the screen while the row holds an unsaved edit (§7.6) opens AM-01, per `admin-map` §3.3 rule 2.

### 5.6 Confirmation lines (`C05`) — exact copy

| After | Arabic | English |
|---|---|---|
| An add | تمت إضافة الفئة "{category name}" | The category "{category name}" was added |
| A rename | تم تغيير اسم الفئة إلى "{category name}" | The category was renamed to "{category name}" |
| A deletion (AM-02 C) | تم حذف الفئة "{category name}" | The category "{category name}" was deleted |

`{category name}` is the name in the dashboard's current language. A new category's confirmation line reminds nobody that it is hidden: its row already says "مخفية — بلا منتجات / Hidden — no products".

### 5.7 What is deliberately not on this screen

- **No product list per category and no link from a row to A-03.** A-03 already shows products grouped by category in this same order.
- **No "move all products to…" action and no merge.** A bulk move is the bulk action A-03 decision 9 rules out.
- **No category image, icon, colour or description.** G-01's chip is a text label (G-01 §5.3, §7.5) and its section title has "no product count, no icon".
- **No sub-categories.** The guest bar is one flat row.
- **No "hide category" switch.** A category is hidden by having no active product, which is the only rule G-01 knows.
- **No reordering of products here.** Product order inside a category is set on A-03 (A-03 decision 2).

## 6. States

### 6.1 Loading

`C14` in the list area; `S01`, `C03` and `C04` stay visible; `B01` is disabled; `C02` and `C11` are hidden. Timeout **10 seconds**, then §6.3 case 1.

An inline-row save and an order save are in-flight states of one control, not screen states: `B06` shows `C10` and its row's fields and `B07` are disabled (inline save, timeout **10 seconds**); an order move is shown on screen at once and `B02`/`B03` are disabled on every row until the save answers (timeout **5 seconds**, `admin-map` §5.4).

### 6.2 Empty

Zero categories: `C13`, two lines, with `B01` as the only control. `C02` and `C11` hidden. This is also the state in which A-04 cannot save a product (A-04 §6.2, `C13`) and G-01 shows its empty state, so `C13`'s second line names what the manager unlocks by adding one.

### 6.3 Error

1. **The list fails to load or times out**: `C15` "تعذّر تحميل الفئات / Categories could not be loaded" and `B08` "إعادة المحاولة / Try again" in the list area. The header, `C03` and `C04` stay; `B01` stays disabled until the list loads.
2. **An order save fails** (no connection, server error, 5-second timeout): the row returns to its previous position, the `#` column is renumbered back, and `C06` appears (`admin-map` §5.4).
3. **An inline-row save fails or times out after 10 seconds**: `S03` stays open with both typed values exactly as typed, `B06` returns to its label and can be clicked again, and `C06` appears. Nothing is lost.
4. **The server refuses a name as a duplicate** that the screen's own check did not catch (another tab saved it first): the duplicate message of §7.3 under the field concerned, exactly as if the screen had caught it.
5. **A deletion confirmed in AM-02 fails** (no connection, server error, 5-second timeout): the row reappears in its old position and `C06` appears.
6. **The server refuses a deletion because the category is no longer empty** (a product was moved into it from another tab): the row reappears with its products count refreshed, `B05` disabled, and `C06` is replaced for 5 seconds by `تعذّر الحذف: أصبحت في هذه الفئة منتجات / Could not delete: this category now holds products`.
7. **Expired session**: A-01 per `admin-map` §4.3. `A-01-C04` warns that unsaved edits were lost.

### 6.4 Success

The list rendered in saved order, every row with its positions, names, counts and store column; `C02` counting; `C03`, `C04` and `C11` visible; `C05` for 5 seconds after an add, a rename or a deletion.

## 7. Field rules

### 7.1 `F01` Arabic name and `F02` English name

| Rule | Value |
|---|---|
| Required | Both |
| Length | 1 to **24** characters after trimming leading and trailing spaces |
| Why 24 | The name is a G-01 chip label that never wraps and never truncates (G-01 §7.5): the chip grows to fit. 24 characters at 14 px is about 200 px, under two-thirds of the 390 px guest bar, so one long chip never fills the row on its own |
| Accepted | Any characters, including digits and punctuation. `F01` is not restricted to Arabic letters and `F02` is not restricted to Latin letters |
| Line breaks | Not accepted; a pasted line break becomes a single space |
| Internal spaces | Kept as typed; two or more consecutive spaces are collapsed to one on blur, in the field, where the manager sees it |
| Uniqueness | **Enforced per language**: no two categories may share an Arabic name, and no two may share an English name, compared after trimming and without regard to letter case. Two chips with the same label in one bar give the guest no way to tell them apart. A rename to the category's own current name is not a duplicate |
| Typing past the limit | Not blocked; `C09` takes the error style and `B06` refuses to save, the same rule as A-04 §7.5 |

### 7.2 Validation timing

Validated when `B06` is clicked or Enter is pressed in either field, never while typing (except the counters). After a failed attempt, each field also re-validates when it loses focus, so a corrected field clears its own message without another attempt. Focus moves to the first failing field, `F01` before `F02`.

### 7.3 Messages — exact wording

| Field | Condition | Arabic | English |
|---|---|---|---|
| `F01` | Empty | أدخل اسم الفئة بالعربية | Enter the category name in Arabic |
| `F01` | Over 24 characters | اسم الفئة بالعربية 24 حرفًا كحد أقصى | The Arabic category name is 24 characters at most |
| `F01` | Duplicate | توجد فئة أخرى بهذا الاسم بالعربية | Another category already has this Arabic name |
| `F02` | Empty | أدخل اسم الفئة بالإنجليزية | Enter the category name in English |
| `F02` | Over 24 characters | اسم الفئة بالإنجليزية 24 حرفًا كحد أقصى | The English category name is 24 characters at most |
| `F02` | Duplicate | توجد فئة أخرى بهذا الاسم بالإنجليزية | Another category already has this English name |

Each message appears in `C16` directly beneath its own field at 13 px, with the field outlined. When both fields fail, both messages are shown at once.

### 7.4 Limits

- Maximum **20 categories** (A-03 decision 10: the guest loads the whole catalog in one request with no pagination, and a bar of more than 20 chips is scrolled, not read). At 20, `B01` is disabled and `C12` states the limit and the remedy.
- Minimum: none. Zero categories is a valid, specified state (§6.2).

### 7.5 Immediate saves

`B02`, `B03` and a deletion confirmed in AM-02 follow `admin-map` §5.4 exactly: applied on screen within 100 ms, reverted on failure (no connection, server error, 5-second timeout) with `C06`. The inline row is not an immediate save: it is committed only by `B06`.

### 7.6 Unsaved-edit detection (inline row)

An open `S03` holds an unsaved edit when either field's trimmed value differs from the value the row opened with (empty in add mode, the saved names in rename mode). A row opened and left untouched, or edited and then typed back to its opening value, is not an unsaved edit and does not open AM-01.

### 7.7 Sizes

Rows 56 px; header row 40 px; ↑/↓ 32 × 32 px with a click area of at least 40 × 40 px; text buttons at least 32 px tall; inline fields 40 px tall. Minimum text size 12 px (the counters); every note and message 13 px. Browser zoom is never disabled. The table needs no horizontal scrolling at 1024 px width.

## 8. Acceptance criteria

1. Opening A-05 shows every category in saved order, one row each, with its position, Arabic name, English name, products count, store column, ↑/↓, "تعديل الاسم / Rename" and "حذف / Delete".
2. The row order on A-05 equals the chip order on G-01 after a catalog fetch, with hidden categories skipped.
3. A category with at least one active product (in stock or out of stock) reads "ظاهرة / Shown"; a category with no active product reads "مخفية — بلا منتجات / Hidden — no products", and G-01 shows no chip and no section for it.
4. A category holding 4 active products and 1 removed product shows `4 + 1 مُزال` / `4 + 1 removed`.
5. ↑ and ↓ move a category exactly one place, renumber the `#` column within 100 ms, send exactly one save request, and are disabled on the first and last rows respectively.
6. When an order save fails or does not answer within 5 seconds, the row returns to its previous place and "تعذّر حفظ التغيير — تحقّق من الاتصال وحاول مرة أخرى / The change could not be saved — check your connection and try again" is shown.
7. "+ فئة جديدة / New category" opens one inline row after the last row, with both fields empty and focus in the Arabic name field.
8. While an inline row is open, "+ فئة جديدة", every ↑, ↓, "تعديل الاسم" and "حذف" are disabled.
9. Saving an inline row with either name empty shows that field's own message from §7.3 beneath it, outlines it, moves focus to it, and sends no request.
10. A name of 25 characters is accepted as typed, turns its counter to the error style, and blocks the save with the "24 characters at most" message for its language.
11. Saving a name that another category already has in the same language — including a difference only in letter case or in leading and trailing spaces — shows the duplicate message for that language and sends no request.
12. Renaming a category to its own current names saves without a duplicate error.
13. A valid add appends the category as the last row, closes the inline row, and shows "تمت إضافة الفئة "{name}" / The category "{name}" was added" for 5 seconds; the new row reads "مخفية — بلا منتجات / Hidden — no products".
14. A valid rename keeps the category's position and products, closes the inline row, and shows the rename confirmation line.
15. Pressing Enter in either inline field does exactly what "حفظ / Save" does; pressing Esc does exactly what "إلغاء / Cancel" does.
16. "إلغاء / Cancel" on an inline row closes it with no modal, discards the typed values, and in rename mode shows the saved names again.
17. An inline save that fails or does not answer within 10 seconds keeps the row open with both typed values exactly as typed and shows the save-failure line.
18. With an inline row holding an unsaved edit, a sidebar click, "تسجيل الخروج / Sign out" or browser back opens AM-01; with no inline row open, or one with no unsaved edit, they leave immediately.
19. "حذف / Delete" is enabled only on a category with zero products, counting removed products; on every other row it is disabled and the note "لا يمكن حذف فئة فيها منتجات… / A category that holds products cannot be deleted…" is visible under the table.
20. "حذف / Delete" on an empty category opens AM-02 variant C and changes nothing until it is confirmed there.

## 9. Decisions settled on this screen

1. **The list is the guest's chip order**, and it includes hidden categories so a category that gains its first product appears where the manager put it.
2. **"Shown" means at least one active product**, in stock or not, because G-01 renders out-of-stock cards; "Hidden" is the only visibility state and it is computed, never switched.
3. **Delete only when empty, counting removed products**, so no product — not even a removed one that may be restored — ever loses its category. This makes A-03's "بلا فئة / No category" filter option unreachable in practice, which is what A-03 §7.2 calls it: a safety net. **Recorded wording difference:** A-03 §7.2 says a product can lose its category "only when a category was deleted"; under this rule even that cannot happen. A-03 was not edited.
4. **Deletion is permanent**, because nothing but products refers to a category and products are protected by decision 3.
5. **Both names required, 1–24 characters, unique per language**, sized to the guest's never-truncated chip.
6. **Add and rename are one inline row with its own "حفظ / Save".** **Recorded disagreement with the map:** `admin-map` §3.3 rule 3 says "Only A-04 and A-07 have a Save button". A name is two typed values that must be committed together and validated together; it cannot be an immediate single-value save without saving half-typed names. The map's §3.2 A-05 row ("inline row on A-05") already implies a commit control. This file follows the map's A-05 row and records the conflict with rule 3.
7. **AM-01 guards A-05 too.** **Recorded disagreement with the map:** `admin-map` §2.2 lists AM-01 as opening on A-04 and A-07 only, while §3.3 rule 2 says leaving any form with unsaved edits "always" opens AM-01 and there is "no silent loss of typed work anywhere in the dashboard". The inline row is typed work, so rule 2 governs and AM-01 opens from A-05 as well (AM-01 §3.1 lists the A-05 case).
8. **The inline Cancel discards without a modal**, because it does not leave the screen and discarding is its only purpose; AM-01 is for leaving.
9. **One inline row at a time, and the list is frozen while it is open**, so no move or deletion happens under a half-typed name.
10. **Maximum 20 categories**, the number A-03 decision 10 assigned to this screen.
11. **No bulk move, no merge, no image, no sub-category, no hide switch.**
12. **The AM-02 variant C confirm button reads "نعم، احذف / Yes, delete"**, matching the "حذف / Delete" button that opens it; see AM-02 §9 for the recorded difference from the map's single label.
