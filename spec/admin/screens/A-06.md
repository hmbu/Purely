Author: Thinker (Agent 1)

---

## 1. ID and name

- **ID:** A-06
- **Name:** الطلبات / Orders
- **Type:** Full admin screen inside the global frame. Read-only order history with filters, a summary of the filtered set, and CSV export.
- **Language:** the dashboard language. Values that are not interface copy — order numbers, room numbers, guest notes — are never translated or reformatted.

---

## 2. Purpose

Find orders by date, status and room, and state what the filtered set is worth — in total, in cash and by card — so the hotel can reconcile what staff collected.

## 3. Entry and exit points

### 3.1 Entry

| From | Trigger | What A-06 shows |

| Browser reload, a bookmarked or linked A-06 URL | Browser load | The filters and page carried in the URL (§7.6). An invalid value in the URL is replaced by its default, silently, and the URL is rewritten |

### 3.2 Exit

| Action | Destination |
|---|---|
| `B05` an order row | AM-03 for that order; A-06 stays behind it |
| `B02` "تصدير CSV / Export CSV" | Stays on A-06; one file downloads (§7.7) |
| Any filter change, `B03` "تطبيق / Apply", `B04` "مسح عوامل التصفية / Clear filters" | Stays on A-06; the summary and the list re-fetch, page returns to 1, the URL updates |
| `B06` / `B07` previous / next page | Stays on A-06; the list re-fetches, the summary does not change, the URL updates |
| `B01` "تحديث / Refresh" | Stays on A-06; summary and current page re-fetch with the same filters |
| Any sidebar item | That screen |

Nothing on A-06 or in AM-03 changes an order. There is no accept, no status change, no cancel, no edit, no refund and no contact control anywhere on this screen (`admin-map` §1; locked decision 5 transitions belong to the staff interface).

## 5. Content

### 5.1 What the screen answers

Three questions, in the order the screen is laid out: **which orders** (filters), **what they add up to** (summary strip), **each one** (table, then AM-03). The strip is computed over the **whole filtered set**, every page, never over the visible page only.

### 5.2 The summary strip (`S03`)

All five figures use the definitions of `admin-map` §5.6, applied to the filtered set:

1. `C06` **الطلبات / Orders** — every order in the filtered set, whatever its status.
2. `C07` **المسلَّمة / Delivered** — orders in the set whose status is `تم التوصيل / Delivered`.
3. `C08` **الإيراد / Revenue** — the sum of the stored totals of those delivered orders.
4. `C09` **منها نقدًا / Of which cash** — the sum of the stored totals of delivered orders whose payment method is cash. This is the amount staff are meant to have collected in cash for the set, because the stored payment choice is what the hotel reconciles (the staff interface records no "method actually used").
5. `C10` **منها بطاقة / Of which card** — the same for card.

`C09` + `C10` = `C08`, always, because every order carries exactly one of the two methods (G-04 §7.3). With the status filter set to anything but "كل الحالات / All statuses" or "تم التوصيل / Delivered", `C07`–`C10` read `0` and `0.00` — correct under the delivered-only rule, and `C11` says why.

### 5.3 An order row (`C13`), start edge to end edge

| Column | Width | Contents |
|---|---|---|
| Order | 110 px | The server order number exactly as stored: Western digits, no "#", no padding (G-05 §7.1) |
| Time | 150 px | Submission time, `DD/MM/YYYY HH:MM`, hotel time zone, laid out left-to-right in both languages |
| Room | 100 px | The room number string exactly as the guest sent it, 15 px bold, leading zeros kept, letters in the case typed, laid out left-to-right in both languages. Never truncated (at most 6 characters, A-07 §5.4) |
| Items | 120 px | The sum of quantities on the order, with the wording of G-01 §7.3: `منتج واحد` / `1 item`, `منتجان` / `2 items`, `{N} منتجات` / `{N} items` (3–10), `{N} منتجًا` / `{N} items` (11 and above) |
| Total | 130 px | The stored total, two decimals, currency label and position per G-01 §7.2 |
| Payment | 120 px | `بطاقة` / `Card` or `نقدًا` / `Cash`, the labels of G-04 B03/B04 line 1 |
| Status | flexible | The current status with the canonical label of G-01 §5.2, 13 px, in a 1 px gray outlined pill. No colour, no icon |

Rows are sorted by submission time, **newest first**. There is no other sort order and no sortable column header.

### 5.4 Pagination

**50 orders per page.** A-03 has no pagination because the catalog is capped at 200 rows; order history is not capped by anything but the 365-day retention, so a busy hotel's month does not fit on one screen. Page changes re-fetch only the table; the summary covers the whole filtered set and does not change between pages.

### 5.5 What is deliberately not on this screen

- **No action on an order.** No accept, no status change, no cancel, no edit, no refund, no re-send to staff (`admin-map` §1).
- **No live board.** No polling, no auto-refresh, no sound. `C02` prints when the data was fetched (A-02 decision 8).
- **No guest identity column**, because an order has none (locked decision 4).
- **No per-product filter, no free-text search of notes, no amount filter.** Date, status and room answer the reconciliation question; a product question is answered by A-02's best sellers.
- **No charts** (`admin-map` §1).
- **No bulk selection and no printing.** The CSV is the way out of the dashboard.

## 6. States

### 6.1 Loading

- **Entry, filter change, refresh**: the five figure values and the table area are replaced by skeletons (`C17` in the table, gray bars in the cards); the header, the filter row, `C05` and `C11` stay usable. `B02` is disabled.
- **Page change**: only the table is replaced by `C17`; the summary keeps its values.
- Timeout **10 seconds**, then §6.3.
- **Export**: `B02` shows `C03` "جارٍ التصدير… / Exporting…"; the rest of the screen stays usable. Timeout **60 seconds** (a year of orders is a large file), then §6.3 case 3.

### 6.2 Empty

- **No order has ever been submitted** (or none within 365 days) and every filter is at its default: `C15`, two lines. The summary strip shows `0`, `0`, `0.00`, `0.00`, `0.00`. `B02` disabled. `S05` hidden.
- **Filters match nothing**: `C16` with `B04` "مسح عوامل التصفية / Clear filters" beneath it. The filter row stays populated so the manager can see what was asked for. The strip shows zeros. `B02` disabled.
- When the default filters (last 30 days) match nothing but older orders exist, `C16` is shown, not `C15`: "no orders yet" would be false.

### 6.3 Error

1. **The summary or the list fails to load or times out** (10 s): the table area shows `C18` "تعذّر تحميل الطلبات / Orders could not be loaded" with `B08` "إعادة المحاولة / Try again"; the figure cards show `—` in place of every value, never `0`, because a failed fetch is not an empty period. `B08` re-fetches both.
2. **A filter field holds an invalid value**: `C04` under that field with the exact message of §7.2 or §7.3; the list and the summary keep showing the last valid filter set; `B02` is disabled until the field is corrected or cleared.
3. **The export fails or times out** (60 s): `C19` under the header; nothing downloads; `B02` returns to its label and can be clicked again.
4. **Expired session**: A-01 per `admin-map` §4.3; the A-06 URL with its filters is the remembered address, so signing in returns to the same filtered view (A-01 §3.2).

### 6.4 Success

The filters applied, the five figures for the filtered set, the current page of up to 50 rows newest first, `C02` with the fetch time, `S05` when there is more than one page.

## 7. Field rules

### 7.1 Defaults and how filters combine

| Filter | Default | Values |
|---|---|---|
| `F01` Period | آخر 30 يومًا / Last 30 days (`admin-map` §5.6) | Today, Last 7 days, Last 30 days, Custom range |
| `F04` Status | كل الحالات / All statuses | All, or exactly one of the five statuses of locked decision 5 |
| `F05` Room | empty (no room filter) | One room number |
| Page | 1 | 1 to the last page |

- The three filters combine with AND.
- Period boundaries follow A-02 §7.1 exactly: `اليوم / Today` = 00:00:00 of today to now; `آخر 7 أيام` = the 7 calendar days ending today, inclusive; `آخر 30 يومًا` = the 30 calendar days ending today, inclusive; all in the hotel time zone from A-07.
- An order belongs to a period by its **submission** time (A-02 §5.3, decision 5), so a filtered set never changes because an order's status changed later — only its status column and the figures that depend on status do.
- Any filter change returns the page to 1.
- Unlike A-02's period (A-02 §7.1), A-06's filters **are** kept in the URL and survive a reload (`admin-map` §3.3 rule 6): A-06 is where a specific view is looked up and linked to.

### 7.2 `F02` From and `F03` To (custom range)

| Rule | Value |
|---|---|
| Required | Both, when Custom range is selected |
| Format | `DD/MM/YYYY`, typed. Day and month may be typed with one digit (`1/9/2026`) and are shown padded on blur (`01/09/2026`). Arabic-Indic digits are converted to Western digits as typed. `-` and `.` typed as separators are converted to `/` |
| Picker | None in version 1. A typed date is exact and testable; a calendar widget is a component to build, translate and make RTL for the same result |
| Range | From ≤ To; To ≤ today; From ≥ the earliest available date printed in `C05` (today minus 364 days). A range of one day (From = To) is valid |
| Applied | Only by `B03` "تطبيق / Apply" or Enter, and only when both fields pass |

| Condition | Arabic | English |
|---|---|---|
| Empty | أدخل التاريخ | Enter the date |
| Not in `DD/MM/YYYY` form | اكتب التاريخ بالصيغة يوم/شهر/سنة، مثل 22/09/2026 | Write the date as DD/MM/YYYY, for example 22/09/2026 |
| Not a real calendar date (`31/02/2026`) | هذا التاريخ غير موجود | This date does not exist |
| After today | لا يمكن اختيار تاريخ بعد اليوم | You cannot choose a date after today |
| Before the earliest available date | تُحفظ الطلبات 365 يومًا فقط — أقدم تاريخ متاح {DD/MM/YYYY} | Orders are kept for 365 days only — the earliest available date is {DD/MM/YYYY} |
| From is after To (shown under `F02`) | تاريخ البداية بعد تاريخ النهاية | The start date is after the end date |

One message per field, the first applicable in the table's order.

### 7.3 `F05` Room

| Rule | Value |
|---|---|
| Accepted | Western digits `0–9`, Latin letters `A–Z` `a–z`, the hyphen `-` and a single space; Arabic-Indic and Extended Arabic-Indic digits are converted to `0–9` as typed. This is the wider of the two room-number formats of A-07 §5.4, **whichever format is currently selected**, because stored orders may date from a period when the other format was in force |
| Length | 1 to 6 characters after trimming |
| Match | **Exact**, on the whole room number, after trimming, without regard to letter case: `12b` finds orders sent as `12B` and as `12b`. `30` does **not** find `305`. A partial match would turn a room lookup into a list of every room containing a digit |
| Leading zeros | Significant, exactly as on the guest side (G-04 §7.1): `0305` does not find `305` |

| Condition | Arabic | English |
|---|---|---|
| A character outside the accepted set | رقم الغرفة يحتوي على أرقام وحروف لاتينية وشرطة أو مسافة فقط | A room number contains only digits, Latin letters, a hyphen or a space |
| More than 6 characters | رقم الغرفة 6 خانات كحد أقصى | A room number is 6 characters at most |

### 7.4 Figures and values

- Counts: whole numbers; a comma thousands separator at 1000 and above in both languages (A-02 §7.3).
- Amounts: two decimals always; currency label from A-07 at the time of viewing, position per G-01 §7.2. A later change of the label on A-07 re-labels past amounts on this screen; it never changes an amount (A-07 §5.2).
- Every total shown is the **stored** order total, never recomputed from current prices (G-07: "the total is never recomputed").
- Dates and times: hotel time zone from A-07; the browser's time zone is never used.

### 7.5 Retention

Orders are kept for **365 days** from submission (`admin-map` §6 flag 6). `C05` prints the earliest available date, recomputed each day. Nothing older can be filtered, listed or exported.

### 7.6 URL

The period (or the two custom dates), the status, the room and the page are carried in the A-06 URL, so a filtered view can be reloaded, bookmarked, and opened from A-02 already filtered. Scroll position and an open AM-03 are not in the URL.

### 7.7 CSV export

| Rule | Value |
|---|---|
| Scope | Every order in the filtered set, every page, newest first — exactly the orders the summary strip counts |
| One row per | Order. The totals column can then be summed in a spreadsheet without counting any order twice |
| Encoding | UTF-8 with a byte-order mark, so Arabic opens readably in a spreadsheet; comma separator; every value that contains a comma, a double quote or a line break is wrapped in double quotes, with inner double quotes doubled; lines end with CRLF |
| Header row | Column names in the dashboard's current language, in this order: رقم الطلب / Order number · التاريخ / Date · الوقت / Time · الغرفة / Room · الحالة / Status · الدفع / Payment · المبلغ الذي سيدفع به / Amount the guest will pay with · المنتجات / Items · عدد القطع / Units · الإجمالي ({label}) / Total ({label}) · الملاحظات / Notes · آخر تغيير للحالة / Last status change · سبب الإلغاء / Cancellation reason |
| Values | Date `DD/MM/YYYY`; time `HH:MM`; last status change `DD/MM/YYYY HH:MM` — all in the hotel time zone. Status and payment as the dashboard-language labels of §5.3. Amount the guest will pay with: the whole number the guest typed (G-04 §7.4), empty for card orders and for cash orders without one. Items: `{qty} × {product name}` for each line in order, separated by ` \| `, names in the dashboard's current language (AM-03 §5.3 explains which name). Units: the sum of quantities. Total: the stored total as a plain number with two decimals and a `.` separator, **no currency label in the cell**, so the column is numeric; the label is in the column name. Notes: exactly as the guest typed them, line breaks kept inside the quoted cell. Cancellation reason: exactly as stored, empty unless Cancelled |
| Spreadsheet-formula guard | Any cell whose value begins with `=`, `+`, `-`, `@`, a tab or a carriage return is written with a leading apostrophe `'`. Guest notes are typed by anyone who scans the QR code; a note must never run as a formula on the hotel's computer |
| File name | `orders_{from}_{to}.csv` with dates as `YYYY-MM-DD` (for Today, the same date twice), Western digits — for example `orders_2026-08-24_2026-09-22.csv` |
| Size limit | None beyond retention: at most 365 days of orders |
| Timeout | 60 seconds (§6.3 case 3) |

### 7.8 Sizes

Rows 52 px; header row 40 px; figure cards 88 px; filter fields 40 px; every clickable element at least 36 px tall. Minimum text size 13 px. Browser zoom is never disabled. The table needs no horizontal scrolling at 1024 px width.

## 8. Acceptance criteria

1. Opening A-06 from the sidebar shows the last 30 days, all statuses, no room filter, page 1, and the URL carries those values.
2. Opening A-06 from A-02's new-orders row shows status = "جديد / New" and the last 30 days.
3. Rows are sorted by submission time, newest first, 50 per page; the pagination row is hidden when the filtered set has 50 orders or fewer.
4. Each row shows the order number, the submission date and time in `DD/MM/YYYY HH:MM`, the room number exactly as sent, the item count in the wording of G-01 §7.3, the stored total with two decimals, "بطاقة / Card" or "نقدًا / Cash", and the canonical status label.
5. A room number sent as `0305` is shown as `0305`, and one sent as `12b` is shown as `12b`.
6. The status filter offers exactly "كل الحالات / All statuses" and the five labels "جديد / New", "تم القبول وجارٍ التحضير / Accepted & preparing", "في الطريق / On the way", "تم التوصيل / Delivered", "ملغى / Cancelled".

## 9. Decisions settled on this screen

1. **Read-only, with no exception.** A-06 reports orders; locked decision 5's transitions belong to the staff interface (`admin-map` §1).
2. **The summary covers the whole filtered set**, never the visible page, and splits delivered revenue into cash and card so the hotel can reconcile against the stored payment choice.
3. **Revenue is delivered-only**, defined once in `admin-map` §5.6 and stated on screen by the same footnote as A-02.
4. **A failed fetch prints `—`, never `0`**, because a failure is not an empty period (A-02 decision 9's rule, applied to figures).
5. **Newest first, 50 per page, no other sort.** One order, one test.
6. **Custom dates are typed `DD/MM/YYYY`, with no calendar picker** in version 1, and the range is bounded by today and by the 365-day retention.
7. **The room filter is an exact, case-insensitive match** and accepts the wider room-number format regardless of the A-07 setting, because history outlives a format change.
8. **Filters and page live in the URL**, unlike A-02's period, because this is the screen that is linked to and bookmarked.
9. **CSV: one row per order, UTF-8 with BOM, numeric totals without a currency label, a formula guard on every cell.** Guest notes are untrusted text.
10. **Export timeout 60 seconds**, longer than the 10-second fetch limit, because a year of orders is one file.
11. **Retention 365 days** (`admin-map` §6 flag 6), printed on the screen with the earliest available date.
