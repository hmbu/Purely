# A-01 — تسجيل الدخول / Sign in

Author: Thinker (Agent 1)
Status: **Draft** (status is changed only by the orchestrator)
Governing documents: `/CLAUDE.md`; `/spec/admin/admin-map.md` §4.3 (session rules), §6 flag 4 (one account, no self-service reset).
Conventions reused from the guest spec, not re-decided here: Western digits 0–9 in both languages; Arabic (RTL) by default with an English toggle; body copy never smaller than 13 px on the dashboard.

---

## 1. ID and name

- **ID:** A-01
- **Name:** تسجيل الدخول / Sign in
- **Type:** Full admin screen, its own URL, the only screen reachable without a session. It does **not** show the global frame (`AF-…`): there is no sidebar, no hotel name, no sign-out.
- **Language:** Arabic (RTL) by default; the toggle `A-01-B02` switches to English. The choice is saved in this browser and is the same choice the rest of the dashboard uses.

---

## 2. Purpose

Let the one manager account into the dashboard, and let nobody else in.

---

## 3. Entry and exit points

### 3.1 Entry

| From | Trigger | What A-01 shows |
|---|---|---|
| The dashboard URL, no valid session | Browser load | Default state (§6.5), both fields empty, focus in `F01` |
| Any admin screen | "تسجيل الخروج / Sign out" (`AF-B07`) | Default state with `C03` "تم تسجيل خروجك / You are signed out" |
| Any admin screen | 60 minutes of inactivity, or a request refused because the session expired | Default state with `C04` (§5.3), and the requested address remembered (§3.2) |
| A-01 | A failed sign-in attempt | Error state (§6.3): the password field cleared, the email kept, `C02` showing the message |
| A deep link to any admin URL with no session | Browser load | Default state; the requested address is remembered (§3.2) |

### 3.2 Exit

| Action | Destination |
|---|---|
| "تسجيل الدخول / Sign in" with a correct email and password | The address the manager was trying to reach when the session was missing or expired, if there was one and it is an admin URL; otherwise **A-02 Overview**. A remembered address is used once and then forgotten |
| "تسجيل الدخول" with a wrong email or password | Stays on A-01, error state (§6.3) |
| Attempt 5 within 15 minutes fails | Stays on A-01, locked state (§6.6) |
| Language toggle `B02` | Stays on A-01, re-rendered in the other language; typed values kept exactly as typed |

There is no other way out of this screen: no "continue as guest", no link to the store, no registration.

## 5. Content

### 5.1 The card

Top to bottom: `C01` title, then `C03` or `C04` when one applies, then the email label and `F01`, then the password label and `F02` with `B03` inside it, then `C02` when an error applies, then `B01`. `B02` sits above the card and `C06` below it.

### 5.2 What is deliberately not here

- **No "remember me".** The session rule is one rule (60 minutes idle, `admin-map` §4.3); a checkbox that quietly extends it makes the dashboard's own timeout notice a lie.
- **No password reset by email.** Version 1 has one account created at installation (`admin-map` §6 flag 4). `C06` states the real recovery path instead of offering a button that cannot work.
- **No hotel name and no logo.** Before sign-in the dashboard has not loaded any hotel's settings; printing a name here would mean either a hard-coded value or a leak of which hotel this URL belongs to.
- **No "sign in" link to the guest store**, and no mention of the QR code. This screen is for one person.

### 5.3 Notices

`C03` and `C04` are the only two notices. `C04`'s copy names the 60-minute rule and the loss of unsaved edits, because the manager's most likely previous action was typing into A-04 or A-07.

## 6. States

### 6.1 Loading

The screen itself does not load data. The only in-flight state is the sign-in request: `B01` shows `C05` "جارٍ التحقق… / Checking…", both fields and `B03` are disabled, nothing else changes. Timeout **10 seconds**, after which the connection message in §7.4 is shown.

### 6.2 Empty

Not reachable: the screen is two fields and a button, which are always present.

### 6.3 Error

Three error situations, all shown in `C02`, all with the exact copy of §7.4, none with a modal or a toast:

1. A field is empty or malformed → the field's own message.
2. Email and password do not match an account → the credentials message. The password field is cleared, the email is kept, focus moves to the password field. **The message never says which of the two was wrong.**
3. The request failed or timed out → the connection message. Both values are kept, nothing is cleared.

### 6.4 Success

The request succeeded: the screen is replaced within 100 ms by the remembered address or A-02. No welcome message, no interstitial.

### 6.5 Default

Card shown, both fields empty, focus in `F01`, `B01` disabled, `C02` hidden, `C06` visible.

### 6.6 Locked

After **5 failed attempts within 15 minutes from this browser**, the screen locks for **15 minutes from the fifth failure**:

- `F01`, `F02`, `B03` and `B01` are disabled (50 % opacity).
- `C02` reads: `تم إيقاف المحاولات مؤقتًا بعد 5 محاولات فاشلة. حاول مرة أخرى بعد {N} دقيقة.` / `Sign-in is paused after 5 failed attempts. Try again in {N} minutes.` `{N}` counts down in whole minutes and is never below 1.
- `C06` stays visible, so the recovery path is readable while locked.
- Reloading the page does not clear the lock. When the 15 minutes pass, the screen returns to the default state with both fields empty.

## 7. Field rules

### 7.1 `F01` Email

| Rule | Value |
|---|---|
| Required | Yes |
| Accepted | A single email address: at least one character, then `@`, then at least one character, a `.`, and at least two more characters. Leading and trailing spaces are trimmed before validation and before sending |
| Length | 5 to 120 characters after trimming |
| Case | Compared without regard to case; sent as typed |
| Keyboard / input type | Email keyboard; `autocomplete` = username; `autocapitalize` off; spellcheck off |
| Paste | Allowed |

### 7.2 `F02` Password

| Rule | Value |
|---|---|
| Required | Yes |
| Accepted | Any characters, including spaces; no character is stripped or rewritten |
| Length | 8 to 72 characters. Nothing on this screen states the rule before a failed attempt; the too-short message names it |
| Masked | Yes, until `B03` is used |
| Keyboard / input type | Password; `autocomplete` = current-password; autocorrect, autocapitalize and spellcheck off |
| Paste | Allowed — a password manager must work |

### 7.3 Validation timing

Validated when `B01` is clicked or Enter is pressed, never while typing. A visible message is cleared the moment either field is edited. The failed-attempt counter increases only for a request that reached the server and was refused; a connection failure does not count toward the lock.

### 7.4 Messages — exact wording

| Condition | Arabic | English |
|---|---|---|
| Email empty | أدخل البريد الإلكتروني | Enter your email |
| Email malformed | تحقّق من صيغة البريد الإلكتروني | Check the email address |
| Password empty | أدخل كلمة المرور | Enter your password |
| Password shorter than 8 characters | كلمة المرور 8 أحرف على الأقل | Your password is at least 8 characters |
| Wrong email or password | البريد الإلكتروني أو كلمة المرور غير صحيحة | Your email or password is incorrect |
| Request failed or timed out (10 s) | تعذّر الاتصال — تحقّق من الاتصال وحاول مرة أخرى | Could not connect — check your connection and try again |
| Locked (§6.6) | تم إيقاف المحاولات مؤقتًا بعد 5 محاولات فاشلة. حاول مرة أخرى بعد {N} دقيقة. | Sign-in is paused after 5 failed attempts. Try again in {N} minutes. |

When both fields are invalid at once, both messages are shown in `C02` on their own lines, email first.

### 7.5 Sizes

Card 400 px wide; fields 44 px tall; `B01` 44 px tall; title 22 px; labels 13 px; field text 15 px; `C02`, `C03`, `C04`, `C06` 13 px. Minimum text size on the screen is 13 px. Browser zoom is never disabled.

## 8. Acceptance criteria

1. Opening any dashboard URL without a valid session shows A-01 with an empty email field focused, an empty password field, and "تسجيل الدخول / Sign in" disabled.
2. A-01 shows no sidebar, no top bar, no hotel name and no sign-out control.
3. "تسجيل الدخول" becomes enabled only when both fields contain at least one character.
4. Pressing Enter in the password field does exactly what clicking "تسجيل الدخول" does.
5. Signing in with correct credentials opens the admin address that was requested before the sign-in was demanded; when there was none, it opens A-02.
6. That remembered address is used once: signing out and signing in again afterwards opens A-02.
7. Signing in with a wrong password shows exactly "البريد الإلكتروني أو كلمة المرور غير صحيحة / Your email or password is incorrect", clears the password field, keeps the email, and never states which of the two was wrong.
8. Signing in with an email that has no account shows the identical message as criterion 7.
9. An empty or malformed email shows its own message from §7.4 without a request being sent.
10. A password shorter than 8 characters shows "كلمة المرور 8 أحرف على الأقل / Your password is at least 8 characters" without a request being sent.
11. While the request is in flight, the button label reads "جارٍ التحقق… / Checking…", both fields are disabled, and further clicks send no second request.
12. A request that does not answer within 10 seconds shows the connection message and keeps both typed values.
13. A connection failure does not increase the failed-attempt count.
14. After 5 refused attempts within 15 minutes, both fields and the button are disabled, the locked message names 5 attempts and counts down whole minutes, and reloading the page does not clear the lock.
15. The lock clears by itself 15 minutes after the fifth failure and the screen returns to the default state with both fields empty.
16. "إظهار / Show" reveals the password and changes its own label to "إخفاء / Hide"; sending a sign-in request re-masks it.
17. Pasting into either field is accepted; the email is trimmed of leading and trailing spaces before validation; the password is never trimmed, stripped or rewritten.
18. The language toggle re-renders A-01 in the other language and direction, keeps both typed values exactly as typed, and the choice is still in force on the next screen after signing in.
19. "هل نسيت كلمة المرور؟ … / Forgot your password? …" is visible in the default, error and locked states, and is plain text — clicking it does nothing and it contains no address or phone number.
20. Signing out from any admin screen shows A-01 with "تم تسجيل خروجك / You are signed out".
21. An idle timeout shows A-01 with the 60-minute notice naming the loss of unsaved edits, and that notice takes precedence over the signed-out notice.
22. Any visible message disappears as soon as either field is edited.
23. All copy on the screen exists in Arabic and English, and every number shown uses Western digits 0–9.
24. The screen contains no "remember me", no registration link, no password-reset link, and no link to the guest store.

## 9. Decisions settled on this screen

1. **The dashboard has a login; the guest store does not.** Locked decision 4 governs guests only. Prices, stock and the room-number format cannot sit behind a bare URL.
2. **One manager account per hotel, created at installation.** No self-signup, no second user, no roles in version 1 (`admin-map` §6 flag 4).
3. **No self-service password reset.** `C06` names the real recovery path instead of a button that would need email infrastructure this version does not have. "Change password" for an already signed-in manager lives on A-07.
4. **One message for a wrong email and a wrong password**, so the screen never confirms that an address is a real account.
5. **Failure lock: 5 attempts in 15 minutes, 15-minute pause, per browser**, surviving a reload; connection failures excluded, because punishing a weak connection locks out the only account the hotel has.
6. **No "remember me".** One session rule, stated once, honoured everywhere.
7. **Password length 8–72, paste allowed, no composition rules enforced on this screen** — the rule that is enforced is stated in A-07, where a password is chosen.
8. **The requested address is remembered once** so a bookmarked filtered order view survives an expired session.
9. **Sign-in timeout 10 seconds**, matching the catalog timeout the guest side already uses (G-01 §6.1), so the product has one waiting limit.
