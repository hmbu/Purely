# AM-01 — تغييرات غير محفوظة / Unsaved changes

Author: Thinker (Agent 1)
Status: **Draft**
Governing documents: `/spec/admin/admin-map.md` §2.2 (AM-01 row), §3.2 (AM-01 row), §3.3 rules 2 and 5, §4.1 (`AF-B07`), §4.3 (session rules); A-04 §3.1, §3.2, §5.7, §6.1, §6.2, §7.8, decision 13; A-05 §5.5, §7.6, decision 7; A-07 §3.2, §5.4.4, §5.6, §7.8.
Conventions reused, not re-decided here: Western digits 0–9; Arabic (RTL) dashboard by default; body copy never smaller than 13 px.

---

## 1. ID and name

- **ID:** AM-01
- **Name:** تغييرات غير محفوظة / Unsaved changes
- **Type:** Modal, no URL. Opens on top of A-04, A-05 or A-07 (the "origin screen") when a navigation would leave a form with an unsaved edit. It does not change the active sidebar item (`admin-map` §4.2).
- **Language:** the dashboard language.

---

## 2. Purpose

Stop a navigation that would lose typed work, and let the manager save it, discard it, or stay.

---

## 3. Entry and exit points

### 3.1 Entry

AM-01 opens when, and only when, one of these navigations is attempted while the origin screen holds an unsaved edit as that screen defines it:

| Origin | Unsaved edit defined by | Navigations that open AM-01 |
|---|---|---|
| A-04 Product details | A-04 §7.8 | `A-04-B02` "إلغاء / Cancel"; any sidebar item; `AF-B07` "تسجيل الخروج / Sign out"; browser back |
| A-05 Categories (an open inline row) | A-05 §7.6 | Any sidebar item; `AF-B07`; browser back |
| A-07 Hotel settings (`F01`–`F06` only; the password fields never count, A-07 §5.6) | A-07 §7.8 | Any sidebar item; `AF-B07`; browser back |

It does **not** open for:

- **Closing the tab or the window, or typing another address**: the browser's own "leave site?" prompt is shown instead (`admin-map` §3.3 rule 2). The dashboard cannot draw a modal there.
- **The language toggle `AF-B06`**: it keeps every typed value in place (`admin-map` §4.1).
- **An expired session** (60 minutes idle, or a request refused as expired): the session is already gone, so there is nothing to save with. A-01 opens and `A-01-C04` states that unsaved edits were lost (`admin-map` §4.3).
- **A-05's inline "إلغاء / Cancel"** and Esc in the inline row: they do not leave the screen (A-05 §5.5).
- **A-04's "إزالة من المتجر / Remove from the store"**: AM-02 variant P states the loss of unsaved edits itself (AM-02 `C05`), so two modals are never stacked.
- **A navigation with no unsaved edit**: it happens immediately.

### 3.2 Exit

| Action | Result |
|---|---|
| `B01` "حفظ ومتابعة / Save and continue" — the origin's validation passes and its save succeeds | AM-01 closes and the requested navigation happens (§5.2) |
| `B01` — the origin's validation fails | AM-01 closes; the requested navigation is **cancelled**; the origin shows its validation error state (A-04 §6.3 case 2, A-05 §7.2–§7.3, A-07 §6.3 case 2). Nothing is saved |
| `B01` — the save request fails or times out (10 s) | AM-01 closes; the requested navigation is **cancelled**; the origin shows its own save-failure line (A-04 `C12`, A-05 `C06`, A-07 `C18`) with every typed value kept |
| `B02` "تجاهل التغييرات / Discard changes" | AM-01 closes; the requested navigation happens; the unsaved edits are lost; nothing is saved |
| `B03` "البقاء / Stay on this page", Esc, a backdrop click, or browser back while AM-01 is open | AM-01 closes; the origin is exactly as it was, every typed value kept, focus returned to the element that had it before the navigation was attempted; the requested navigation is forgotten |

## 5. Content

### 5.1 One question, three answers

The card asks nothing it does not need: a title, one sentence stating the consequence, and three buttons. It does **not** list which fields changed. The manager was typing into them seconds ago, and a list of field names would be a second place to keep in step with every form.

Button order, start edge to end edge: `B03` "البقاء / Stay on this page", `B02` "تجاهل التغييرات / Discard changes", `B01` "حفظ ومتابعة / Save and continue". On open, keyboard focus is on `B03`, so Enter and Esc both keep the work: the only answer that loses anything, `B02`, is never the default.

### 5.2 "حفظ ومتابعة / Save and continue" is the origin's own Save

`B01` never has rules of its own. It runs exactly what the origin's own commit control runs — the same validation, the same single request, the same 10-second timeout:

| Origin | `B01` runs | On success, the requested navigation then happens, and… |
|---|---|---|
| A-04 | A-04 `B01` "حفظ / Save" (A-04 §7) | …when the destination is A-03 (A-04 "إلغاء / Cancel", browser back to A-03, or the sidebar "المنتجات / Products"), A-03 opens with the saved row outlined for 3 seconds and the A-03 §5.6 confirmation line, exactly as after A-04's own Save. Any other destination opens directly, with no confirmation line |
| A-05 | A-05 `B06` "حفظ / Save" of the open inline row (A-05 §7) | …the destination opens directly |
| A-07 | A-07 `B01` "حفظ / Save" with the room-number format unchanged (A-07 §5.5) | …the destination opens directly |

When the requested navigation is `AF-B07` "تسجيل الخروج / Sign out", the navigation after a successful save is the sign-out itself: the session ends and A-01 shows `A-01-C03` "تم تسجيل خروجك / You are signed out".

**This is what makes AM-01 the protection against unfinished products that A-04 relies on** (A-04 §5.7, decision 13: "No autosave, no draft … AM-01 is the protection"). `B01` can only store a product that passes every rule of A-04 §7 — both names, a category, a valid price. A form that fails any rule is **not** saved in part, not saved as a draft and not kept anywhere: AM-01 closes, the navigation is cancelled, and A-04 shows which fields to fix. There is no path through AM-01 that puts an incomplete product into the catalog the guest fetches.

### 5.3 When "حفظ ومتابعة" is disabled, and what `C03` says

`B01` is disabled exactly when the origin's own Save could not run now. `C03` states which case applies:

| Case | `C03` Arabic | `C03` English | `B01` becomes enabled when |
|---|---|---|---|
| A-07, the room-number format differs from the saved one. Only AM-04 may save it (A-07 §5.4.4, layer 2) | تغيير صيغة رقم الغرفة يحتاج إلى تأكيد واختبار. اختر «البقاء» ثم «حفظ». | Changing the room number format needs a confirmation and a test. Choose "Stay on this page", then "Save". | Never while AM-01 is open. `B02` and `B03` stay available |
| A-04, an image upload is in flight (A-04 §6.1: Save is disabled during an upload) | يجري رفع صورة. يمكنك الحفظ بعد انتهاء الرفع. | An image is uploading. You can save when the upload finishes. | The upload finishes or fails, while AM-01 is still open; `C03` then disappears |
| A-04, no category exists (A-04 §6.2: Save is disabled) | لا يمكن حفظ منتج قبل إنشاء فئة واحدة على الأقل. | A product cannot be saved before at least one category exists. | Never while AM-01 is open |

A disabled `B01` is always accompanied by `C03`; it is never disabled without a stated reason.

### 5.4 What AM-01 never does

- It never saves anything by itself being open, closed, or dismissed.
- It never keeps discarded edits anywhere: after `B02` the values are gone, with no undo.
- It never opens on top of another modal. AM-02, AM-03 and AM-04 cover the sidebar and the top bar with their backdrops, so no navigation can be attempted while they are open; browser back while AM-04 is open is absorbed by AM-04 (AM-04 §3.2).

## 6. States

### 6.1 Loading

Only while `B01`'s save is in flight: `B01` shows `C04` "جارٍ الحفظ… / Saving…"; `B02`, `B03`, the backdrop, Esc and browser back are ignored. Timeout **10 seconds**, then the save-failure exit of §3.2. AM-01 fetches nothing on open.

### 6.2 Empty

Not reachable: AM-01 opens only when an unsaved edit exists.

### 6.3 Error

AM-01 renders no error of its own. A validation failure or a failed save closes AM-01 and is shown on the origin, where the fields are (§3.2), because the manager cannot fix a field from inside the modal.

### 6.4 Success

`B01`'s save succeeded: AM-01 closes and the requested navigation happens within 100 ms (§5.2).

---

## 7. Field rules

AM-01 has no field. The rules it applies belong to the origin:

- **What counts as an unsaved edit**: A-04 §7.8, A-05 §7.6, A-07 §7.8. A value typed and then returned to its original, or trimmed-equal to it, is not an unsaved edit and never opens AM-01.
- **What `B01` validates and sends**: A-04 §7, A-05 §7, A-07 §7 (settings form only).
- **Timeouts**: 10 seconds, the origin's own save timeout.
- **Sizes**: card 480 px; buttons 44 px tall; title 18 px; body 15 px; `C03` 13 px. Minimum text size 13 px. Browser zoom is never disabled.

## 8. Acceptance criteria

1. On A-04 with an unsaved edit, "إلغاء / Cancel", a sidebar click, "تسجيل الخروج / Sign out" and browser back each open AM-01 and do not navigate.
2. On A-05 with an inline row holding an unsaved edit, a sidebar click, "تسجيل الخروج" and browser back each open AM-01.
3. On A-07 with an unsaved edit in any of the six settings, a sidebar click, "تسجيل الخروج" and browser back each open AM-01; text typed only in the password fields never opens it.
4. With no unsaved edit, none of those navigations opens AM-01.
5. Changing a value and changing it back, or adding only a trailing space, does not open AM-01.
6. Switching the dashboard language never opens AM-01.
7. Closing the tab with an unsaved edit shows the browser's own leave prompt, not AM-01.
8. AM-01 shows the title "تغييرات غير محفوظة / Unsaved changes", the sentence of `C02`, and three buttons in this order from the start edge: "البقاء / Stay on this page", "تجاهل التغييرات / Discard changes", "حفظ ومتابعة / Save and continue".
9. On open, keyboard focus is on "البقاء"; pressing Enter or Esc closes AM-01 and leaves the origin exactly as it was.
10. A backdrop click and browser back while AM-01 is open behave exactly like "البقاء".
11. "البقاء" returns to the origin with every typed value kept exactly as typed and forgets the requested navigation.
12. "تجاهل التغييرات" performs the requested navigation, saves nothing, and the edits cannot be recovered.
13. "حفظ ومتابعة" on a valid A-04 form sends exactly one save request, shows "جارٍ الحفظ… / Saving…", and then performs the requested navigation.
14. When "حفظ ومتابعة" on A-04 leads to A-03, the saved row is outlined for 3 seconds and the A-03 §5.6 confirmation line is shown.
15. "حفظ ومتابعة" on an A-04 form with an empty English name saves nothing, closes AM-01, stays on A-04, and shows "أدخل اسم المنتج بالإنجليزية / Enter the product name in English" beneath the field.
16. No sequence of actions through AM-01 stores a product that fails any rule of A-04 §7, and no draft or partial product is stored anywhere.
17. When the save sent by "حفظ ومتابعة" fails or exceeds 10 seconds, AM-01 closes, the navigation does not happen, and the origin shows its own save-failure line with every typed value kept.
18. While the save is in flight, "البقاء", "تجاهل التغييرات", Esc, the backdrop and browser back do nothing, and a second click on "حفظ ومتابعة" sends no second request.
19. On A-07 with the room-number format changed, "حفظ ومتابعة" is disabled and "تغيير صيغة رقم الغرفة يحتاج إلى تأكيد واختبار… / Changing the room number format needs a confirmation and a test…" is shown; "تجاهل التغييرات" and "البقاء" still work.
20. On A-04 during an image upload, "حفظ ومتابعة" is disabled with "يجري رفع صورة… / An image is uploading…", and becomes enabled, with that line removed, when the upload ends while AM-01 is open.
21. On A-04 when no category exists, "حفظ ومتابعة" is disabled with "لا يمكن حفظ منتج قبل إنشاء فئة واحدة على الأقل. / A product cannot be saved before at least one category exists."
22. "حفظ ومتابعة" is never disabled without one of the three lines of §5.3 visible.
23. "حفظ ومتابعة" after "تسجيل الخروج" saves, then ends the session and shows A-01 with "تم تسجيل خروجك / You are signed out".
24. An expired session never shows AM-01; A-01 opens with the notice that unsaved edits were lost.
25. Every string on AM-01 exists in Arabic and English, and the modal re-renders in the other language and direction when the dashboard language is switched before it opens.

## 9. Decisions settled on this screen

1. **"Save and continue" is the origin's own Save**, with no rules of its own, so there is one validation per form and AM-01 cannot drift from it.
2. **A failed validation or save cancels the navigation** and is shown on the origin, where the fields are. This is what makes AM-01 the protection A-04 relies on: it can never store an unfinished product, and nothing is kept as a draft.
3. **"البقاء / Stay on this page" is the default and the Esc/backdrop answer**; the only destructive answer is never the default.
4. **Save is disabled whenever the origin's Save could not run, always with the reason on screen.** For A-07 this keeps AM-04 the only route by which a changed room-number format is saved.
5. **No list of changed fields.**
6. **AM-01 opens on A-05 as well.** **Recorded disagreement with the map:** `admin-map` §2.2 names A-04 and A-07 only; §3.3 rule 2 requires AM-01 for every form with unsaved edits. Rule 2 is followed (A-05 decision 7).
7. **Arabic label kept exactly as the finished screens use it:** A-04 §3.1 and the map both write "البقاء / Stay on this page"; the Arabic is the shorter "البقاء" and the English the longer phrase. It is kept as written, because A-04 already cites it.
8. **Session expiry and tab closing are outside AM-01**, because a dashboard modal cannot run in either case; `A-01-C04` and the browser prompt cover them.
