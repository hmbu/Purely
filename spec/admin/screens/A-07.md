## 1. ID and name

- **ID:** A-07
- **Name:** إعدادات الفندق / Hotel settings
- **Type:** Full admin screen inside the global frame. One form of four settings saved together by one Save, plus a separate password group with its own button.
- **Language:** the dashboard language for labels and buttons. The hotel name and the currency label are edited in **both** languages, side by side, whichever language the dashboard is in.

---

## 2. Purpose

Set the four values the whole store prints or validates against — hotel name, currency label, time zone, room-number format — and change the manager's password.

### 3.2 Exit

| Action | Destination |
|---|---|
| `B01` "حفظ / Save", fields valid, `F06` equal to the saved format | Stays on A-07; one request saves the four settings; `C19` confirms (§6.4) |
| `B01`, fields valid, `F06` different from the saved format | **AM-04**. Nothing is sent until AM-04's "تأكيد التغيير / Confirm change" |
| `B01` with any field invalid | Stays on A-07, error state (§6.3); nothing is sent and AM-04 does **not** open, even when `F06` changed |
| `B03` "تغيير كلمة المرور / Change password", fields valid | Stays on A-07; one request; `C25` confirms and the three password fields are emptied |
| Any sidebar item, `AF-B07` sign out, or browser back **with an unsaved edit** in `F01`–`F06` (§7.8) | AM-01 |
| The same, with no unsaved edit | That destination, immediately. The password fields are emptied (§5.6) |
| Closing the tab with an unsaved edit | The browser's own "leave site?" prompt (`admin-map` §3.3 rule 2) |

A-07 has no Cancel button: it is a destination, not a step, so there is nowhere to cancel back to. A manager who wants to undo edits leaves by the sidebar and chooses "تجاهل التغييرات / Discard changes" in AM-01.

## 5. Content

### 5.1 Hotel name (`S03`)

Two values, one per guest language. G-01 prints the one for the guest's language in its header (G-01 §5.1, `C01`: one line, 18 px, bold, centered between two buttons); the sidebar prints the one for the dashboard's language (`AF-C01`). Both are required here, for the reason A-04 §5.2 gives for product names: G-01's fallback to the Arabic value exists for robustness, not as a way to show the foreign guest an unreadable header. A hotel whose name is the same word in both languages types it twice.

After a successful save, `AF-C01` shows the new name at once, without a reload.

### 5.2 Currency label (`S04`)

- Two text values: the Arabic label (installation default `ر.س`) and the English label (installation default `SAR`).
- **Only the label is editable. Its position is fixed** by G-01 §7.2 — after the amount in Arabic, before it in English — and there is no setting, checkbox or per-product override for it (`admin-map` §5.2 rule 7).
- The label is not a currency conversion. Changing `SAR` to `AED` changes no stored price and no stored order total; it changes the label printed beside every amount, in the store and in this dashboard, including past orders on A-06 and AM-03. `C07` says so on screen, because a manager who changes the label expecting prices to convert would otherwise sell at the old numbers under a new label.
- `C08` repeats the fee ruling of `admin-map` §5.7 here, as the map requires.
- `C06` shows the label as each guest interface will print it, using the typed (not yet saved) labels, so a label is read in place before it is saved.

### 5.3 Time zone (`S05`)

- One IANA time zone for the hotel. Installation default `Asia/Riyadh`.
- It decides, for **this dashboard only**: what "today" means on A-02 and A-06, every period boundary, every date and time printed on A-02, A-06, AM-03, `C14` and in the CSV (`admin-map` §5.6 "A day").
- It changes **nothing on the guest side**: G-07 and G-06 print times in the device's own time zone (G-07 §5.6), and no guest screen reads this value.
- Changing it re-labels the times of past orders and moves orders across day boundaries in reports; it never changes the stored instant of any order. The line `الوقت الآن في هذه المنطقة: {HH:MM} / Time now in this zone: {HH:MM}` lets the manager check the choice against a wall clock before saving.

### 5.4 Room-number format (`S06`) — how OQ-01 is closed operationally

This is the one setting that can break every future order: a guest who cannot type their real room either abandons the order or types a different, valid room and is delivered to a stranger's door (OQ-01, consequences 1–4). Everything below is a decision.

#### 5.4.1 Exactly two presets

| | Preset 1 — `أرقام فقط / Digits only` | Preset 2 — `أرقام وحروف / Digits and letters` |
|---|---|---|
| Source | G-04 §7.1 as approved, character for character | OQ-01 "Proposed alternative", character for character |
| Default | **Yes** — installation default; a hotel that never opens A-07 behaves exactly as the approved guest spec describes | No |
| Accepted characters | Western digits `0–9`; Arabic-Indic `٠–٩` and Extended Arabic-Indic `۰–۹` converted to `0–9` as typed | Western digits `0–9` (Arabic-Indic and Extended Arabic-Indic converted as typed); Latin letters `A–Z`, `a–z`; the hyphen `-`; a single space. Arabic letters are **not** accepted |
| Structure | — | At least one digit; does not begin or end with a separator; no two adjacent separators |
| Length | 1 to 5, after trimming | 1 to 6, after trimming, separators counted |
| Case | — | Accepted in either case and sent exactly as typed; never upper- or lower-cased |
| Leading zeros | Kept as typed | Kept as typed |

There is **no third option, no free text, no regular-expression field, no editable length and no per-wing rule** (`admin-map` §5.5 rule 1). The two presets are stored and sent as two fixed identifiers; the settings request accepts no other value.

#### 5.4.3 What the setting never does

1. **It never rejects a submitted order.** It decides the keyboard and the client-side validation on G-04 only. Whatever room number reaches the server is stored and delivered (`admin-map` §5.5 rule 4). No new guest error state exists for it and none is created.
2. **It never changes a stored order.** Orders keep the room number exactly as sent; A-06 and AM-03 show it as sent.
3. **It never changes a checkout already in progress.** The format travels with the catalog (`admin-map` §5.3) and a guest's browser tab keeps the format it first received **for the life of that tab** — the same lifetime as the G-04 checkout draft (G-04 §7.7). A value typed in a tab is therefore always validated under the rule it was typed under, and a tightened format can never invalidate it (`admin-map` §5.5 rules 4 and 5). A new tab — the next scan of the QR code — gets the current format. This is part of the §5.4.2 contract.

#### 5.4.4 What protects it — five layers

1. **Only two values exist.** No free pattern can be typed, so no malformed rule can be saved (§5.4.1).
2. **The dashboard cannot save a changed format without AM-04.** `B01` opens AM-04 whenever `F06` differs from the saved format; AM-04 closes only by its own two buttons, never by backdrop or Esc (`admin-map` §3.3 rule 5); AM-01's "حفظ ومتابعة / Save and continue" is disabled while the format is changed (AM-01 §5.3), so no navigation route saves it past AM-04.
3. **A live test on the manager's own data.** AM-04's "تأكيد التغيير / Confirm change" is enabled only while a room number typed by the manager passes the **new** rule, run by the same rule definition G-04 will run (AM-04 §5.3). Switching to Digits only in a hotel with a room `A-12` fails in front of the manager before anything is saved.
4. **A check of the hotel's own history.** AM-04 lists how many distinct room numbers in the stored orders the new rule would refuse, with examples (AM-04 §5.2). It informs; it does not block, because a stored room number may itself be a guest's typo.
5. **The server re-checks and records.** A settings request that changes the format must carry the test room number; the server refuses the change unless that value passes the new preset, and it writes the audit record shown in `C14` in the same step. A request that does not change the format carries no test value and is not refused for its absence.

Plus the audit line `C14`: when room numbers start failing, "did someone change this, and when" is answered on this screen (`admin-map` §5.5 rule 6).

### 5.5 One Save for four settings

`F01`–`F06` are saved together by one request, because they are one record the guest's catalog carries. `B01` is disabled while nothing differs from the saved values (§7.8), so a disabled Save is itself the statement "nothing to save". When the format changed, AM-04's Confirm sends this same one request, containing every edited value on the form, not the format alone (`admin-map` §3.2 AM-04 row).

### 5.6 Password group (`S07`)

- The password group is **not** part of the settings form: its own button `B03`, its own request, its own result line. A wrong current password must never block saving the hotel name, and a hotel-name error must never block a password change.
- The three fields are excluded from unsaved-edit detection (§7.8) and are emptied whenever the screen is left, by any route, and after a successful change. `C26` states this on screen. A typed password is never held after the manager has moved on.
- A successful change keeps this browser signed in and ends every other session of the account.
- Wrong current passwords count toward the same per-browser failure counter as A-01 sign-in (A-01 §6.6). The fifth failure within 15 minutes ends the session and opens A-01 in its locked state. An open session must not become a way to guess the password without limit.

### 5.7 What is deliberately not on this screen

- **No store open/closed switch and no opening hours** (`admin-map` §6 flag 3; map §4 decision 16).
- **No fee, service charge, tax or discount setting** (`admin-map` §5.7).
- **No currency position setting, no decimal-places setting, no number-format setting** (G-01 §7.2 fixes them).
- **No default guest language setting.** Arabic is the default by locked decision 7.
- **No logo or image upload.** G-01's header prints a name, not a logo.
- **No custom room-number pattern and no room list.** A room list is backlog G-04-L5.
- **No second account, no email change, no staff accounts** (`admin-map` §6 flag 4).
- **No Cancel button** (§3.2).

## 6. States

### 6.1 Loading

- **Fetching the settings**: `C27` in place of the form; `S07` hidden. Timeout **10 seconds**, then §6.3 case 1.
- **Saving the settings** (`B01`, format unchanged): `B01` reads `C21` "جارٍ الحفظ… / Saving…"; `F01`–`F06` disabled; `S07` stays usable. Timeout **10 seconds**, then §6.3 case 3. A save through AM-04 shows its in-flight state inside AM-04 (AM-04 §6.1).
- **Changing the password**: `B03` reads `C24` "جارٍ التغيير… / Changing…"; `F07`–`F09` disabled; the settings form stays usable. Timeout **10 seconds**, then §6.3 case 5.

### 6.2 Empty

Not reachable. Every hotel has a saved settings record from installation, holding the four installation values (the two hotel names typed by the installer, `ر.س` / `SAR`, `Asia/Riyadh`, Digits only). A response with no settings record is treated as a load error (§6.3 case 1), never as an empty form: an empty form would invite saving blank values over a working store.

### 6.3 Error

1. **The settings could not be fetched**: `C28` "تعذّر تحميل الإعدادات / Settings could not be loaded" with `B04` "إعادة المحاولة / Try again". No field is shown, so no default can be mistaken for a saved value.
2. **Validation failed on Save**: each failing field outlined with its message from §7 in `C16` beneath it; `C17` "راجع الحقول المميزة بالأعلى / Check the highlighted fields above" above `B01`; focus on the first failing field in reading order; nothing sent; AM-04 not opened.
3. **The settings save failed or timed out**: `C18` "تعذّر الحفظ — تحقّق من الاتصال وحاول مرة أخرى. لم يُفقد ما كتبته. / Could not save — check your connection and try again. Nothing you typed was lost."; every typed value kept; `B01` clickable again.
4. **Password validation failed**: the message of §7.5 under the field concerned.
5. **The password request failed or timed out**: `C25` with the connection message of §7.5; the three fields keep their values.
6. **Expired session**: A-01 per `admin-map` §4.3; `A-01-C04` warns that unsaved edits were lost.

### 6.4 Success

- **Settings saved**: every field shows the saved value; `C19` "تم حفظ الإعدادات / Settings saved" for 5 seconds; `B01` disabled again (nothing differs); `AF-C01` shows the new hotel name; when the format changed, `C14` shows the new date, time and account.
- **Password changed**: the three fields emptied; `C25` success line for 10 seconds.

### 6.5 Build variant (b) — preset 2 visible but not available

`admin-map` §6 flag 1 lets the owner ship version 1 before the guest files are revised. In that build, and only then:

- `F06` option 2 "أرقام وحروف / Digits and letters" is rendered with its helper text, at 50 % opacity, and cannot be selected.
- `C13` "غير متاح بعد: يجب تحديث واجهة النزيل قبل أن تقبل الحروف. / Not available yet: the guest interface must be updated before it can accept letters." sits directly under it.
- `C15` is hidden, because the format cannot change and AM-04 is therefore unreachable.
- `C14` stays, reading "لم تُغيَّر منذ تركيب النظام / Not changed since the system was installed".
- The server refuses preset 2 in a settings request.
- OQ-01 stays open. Everything else on A-07 is identical.

This file is written for variant (a). The switch between the two is a build decision recorded by the owner, not a setting on this screen.

### 7.6 Validation timing (settings form)

Validated when `B01` is clicked. After a failed attempt, each field also re-validates when it loses focus, so a corrected field clears its own message without another attempt. Nothing is validated while typing except the counters. Focus moves to the first failing field in reading order: `F01`, `F02`, `F03`, `F04`.

### 7.7 Values sent

One settings request carries: both hotel names (trimmed), both currency labels (trimmed), the time zone identifier, the format identifier, and — only when the format changed — the AM-04 test room number as the guest's G-04 would send it (trimmed, digits converted). The password request carries the three password values untouched.

### 7.8 Unsaved-edit detection

The settings form has an unsaved edit when any of `F01`–`F06` differs from the value the form opened with (or was last saved with), comparing trimmed values. Selecting another format and then the saved one again is not an unsaved edit. **`F07`–`F09` never count** (§5.6).

### 7.9 Sizes

Form 720 px wide; fields 44 px tall; radio rows 64 px; buttons 44 px tall; every clickable element at least 36 × 36 px. Minimum text size 12 px (the counters); every note and message 13 px; field text 15 px. Browser zoom is never disabled.

## 9. Decisions settled on this screen

1. **Four settings, one Save, one request**, because they are one record that travels with the guest's catalog. Save is disabled while nothing differs.
2. **The password group is separate**, with its own button and request, never saved by "حفظ", excluded from unsaved-edit detection and emptied on leaving. **Recorded disagreement with the map:** `admin-map` §3.3 rule 3 says only A-04 and A-07 have "a Save button" and rule 2 says no typed work is ever lost silently. The password button is a second commit control on A-07, and typed passwords are discarded on leaving — deliberately, stated on screen by `C26` so the loss is not silent, because holding a typed password across navigation is the wrong default for a credential.
3. **Both hotel names required, 1–24 characters**, sized to G-01's one-line header.
4. **The currency label is 1–4 characters with no digits and no spaces**, its position fixed by G-01 §7.2, and the screen says it is a label, not a conversion.
5. **Time zone is a dashboard-only value**, installation default `Asia/Riyadh`, with a live clock line to check it.
6. **The room-number format has exactly two presets**, copied verbatim from G-04 §7.1 and OQ-01, default Digits only, saved only through AM-04, re-checked by the server against the test value, audited on screen.
7. **Under Digits and letters, the structure message fires on submit only**, never on blur, because it can be fixed by typing one more character — the reasoning G-04 §7.1 applies to its own blur checks. OQ-01 did not state the timing; this is the decision.
8. **A guest tab keeps the format it first loaded for its whole life**, the lifetime of the G-04 checkout draft, so a format change can never invalidate a value already typed (`admin-map` §5.5 rules 4 and 5). This is a guest-build requirement recorded in the §5.4.2 contract for the owner to route; no guest file was edited.
9. **Build variant (b) is fully described** (§6.5) so the owner's choice under `admin-map` §6 flag 1 needs no further specification.
10. **No empty state**: a missing settings record is a load error, so blank values are never offered for saving over a working store.
11. **Wrong current passwords share A-01's per-browser failure counter**, so an unattended open session is not an unlimited password-guessing surface.
12. **Flag for the owner — OQ-01's change list is incomplete.** OQ-01 "What must change if the answer is yes" names G-04, M-01 and M-03 only. Under Preset 2 the following frozen texts also describe the room number as digits, and would need the same routing: G-05 §5.2 and §7.2 ("1–5 Western digits", 48 px box, "read one digit at a time"), G-06 §7 room-number row ("1–5 Western digits", 28 px) and its screen-reader rule ("room digits one at a time"), G-07 §7 room-number row ("Western digits"), and the staff room-number rule (`/spec/staff/staff-map.md` §4 decision 4, "always Western digits"). A six-character label fits each of those boxes at its stated size; only the wording and the screen-reader rule change. None of these files was edited.
13. **Flag for the owner — A-04 `C08` wording.** A-04's validation summary reads "راجع الحقول المميزة بالأسفل / Check the highlighted fields below" but sits above the Save button, after every field (A-04 §5.1). A-07 uses "بالأعلى / above", which matches its position. A-04 was not edited.
