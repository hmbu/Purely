# A-04 — تفاصيل المنتج / Product details

Author: Thinker (Agent 1)
Status: **Draft**
Governing documents: `/spec/admin/admin-map.md` §5.1 (catalog contract), §5.2 (prices), §5.3 (when a change reaches a guest), §5.7 (no fees or tax); G-01 §5.4, §7.2; G-02 §5.4 (description limit); G-03 §5.2.
Conventions reused, not re-decided here: Western digits 0–9 in both languages; currency label from A-07 with the position of G-01 §7.2; two decimals always; the hotel time zone from A-07.

---

## 1. ID and name

- **ID:** A-04
- **Name:** تفاصيل المنتج / Product details
- **Type:** Full admin screen inside the global frame, with **two modes**: *create* (a new product) and *edit* (an existing one). The two modes differ in the title, the Remove button and what Save does; every field and every rule is identical, which is why they are one screen.
- **Language:** the dashboard language for labels and buttons. The product's own content is always edited in **both** languages, side by side, whichever language the dashboard is in.

---

## 2. Purpose

Create or change one product, and show the manager what the guest will see before it is saved.

---

## 5. Content

### 5.1 Form order

Top to bottom: `C11` when it applies · Arabic name and English name side by side · Arabic description and English description side by side · Category · Price with `C04` and `C03` · Image (`C07`, `B05`, `B04`, `C06`) · Stock (`F07`) · `C09` · `C08` or `C12` when they apply · the button row `B01` `B02` … `B03`.

The two languages sit **side by side, never on separate tabs**. A tab would let a product be saved with an empty English name without the manager ever seeing the empty field.

### 5.2 Both languages are required for the name

`F01` and `F02` are both required. The guest interface does carry a fallback — an English interface shows the Arabic name when the English one is missing (G-01 §5.1, G-02 §5.3) — but that fallback exists for robustness, not as a way to ship half a catalog to the foreign guest this product explicitly serves. A product created or edited through A-04 always has both names, so the fallback never triggers for it.

Descriptions are **optional in both languages**, because G-02 already hides its description section entirely when neither exists (G-02 §5.4, decision 9), which is a complete and specified guest experience. If exactly one description is written, the guest sees it in both languages (G-02 §5.4 fallback), and `C05` on the empty field is the manager's only reminder — the form does not block on it.

### 5.3 Price, and what the store does with it

`F06` takes **an amount only**. The currency label is printed beside the field as static text, in the guest's position for the dashboard's current language, and is not part of the value: typing `ر.س` or `SAR` into the field is a character error (§7.4).

On blur, the value is normalised in front of the manager, before any save: Arabic-Indic digits become Western digits, a typed `,` becomes `.`, and the amount is padded to two decimals (`12` → `12.00`, `12.5` → `12.50`). The field then shows exactly what will be stored. Nothing is rewritten silently at save time.

`C04` prints the amount as **both** guest interfaces will render it — `12.00 ر.س` and `SAR 12.00` — no matter which language the dashboard is in, so an Arabic-reading manager still sees what the foreign guest will read. `C03` states, in one line, that this amount is the whole amount (`admin-map` §5.7).

The stored unit price is a decimal with exactly two places. It is never rounded: the only rounding in the product is `quantity × unit price` on the guest side, half up (G-03 §7.2).

**A price change never changes an order that was already submitted** (G-07: the total is stored at submission and never recomputed). It applies to carts built after the guest's next catalog fetch.

### 5.4 Image

- One image per product, optional.
- `B05` opens the file picker. The chosen file is validated in the browser (§7.6) and, if it passes, uploaded at once with the progress state of §6.1. The form shows the uploaded image in `C07` as the **exact square crop the guest will see**: a non-square image is centre-cropped to 1:1, and the preview is that crop, not the original.
- The product keeps its previously saved image until `B01` is used. Cancelling or discarding leaves the saved product untouched.
- `B04` clears the image from the form; after Save the product has none and every guest screen falls back to the gray box with the generic icon (G-01 §5.4).
- No cropping tool, no rotation, no alt text, no second image, no gallery in version 1. Centre-cropping is stated in `C06` so the manager can frame the photo before uploading.

### 5.5 Stock on this screen

`F07` is a form field here: it is saved with the rest of the form when `B01` is used, and Cancel discards it. This deliberately differs from A-03, where the same switch is a one-click immediate action. The difference is stated in both files and is why the two carry different element types: on A-03 stock is the whole edit, on A-04 it is one field among eight and must not commit while the rest of the form is unsaved.

A new product's switch starts **on**. The manager who is adding a product is adding something to sell.

### 5.6 Editing a removed product

`C11` states plainly that no guest can see it. Every field stays editable and savable — correcting a name or a price on a removed product is legitimate — but `F07` is disabled, because stock is meaningless for a product that is not in the store. `B03` reads "استعادة / Restore" and restores it **out of stock** (A-03 §5.6), so a product removed because it ran out never returns on sale by accident.

### 5.7 What is deliberately not on this screen

- **No autosave and no draft.** An unfinished product must not exist in the catalog; the guest fetches whatever is stored. Typed work is protected by AM-01, not by a hidden draft, and is not restored after a reload.
- **No delete.** Removal is archiving (A-03 §5.4).
- **No cost price, margin, supplier, barcode, SKU, tax class, weight or preparation time.** None of them has anywhere to go on the guest side, and a tax class would contradict `admin-map` §5.7.
- **No discount, sale price or "compare at" price** — G-01 §5.4 states the card has no strikethrough and no discount.
- **No stock quantity or low-stock threshold.** Stock is yes/no (G-03 §5.6).
- **No scheduling** ("available from 18:00"): store hours are not modelled (map §4 decision 16).
- **No per-product notes to staff, no allergen list, no nutrition panel.**
- **No duplicate-product button.**

## 6. States

### 6.1 Loading

- **Fetching an existing product**: `C10` skeleton in place of the form; the title and the button row are hidden until the data arrives. Timeout **10 seconds**, then §6.3 case 1.
- **Uploading an image**: `C07` shows the gray box with a centred text line `جارٍ الرفع… / Uploading…` at 13 px; `B05`, `B04` and `B01` are disabled; every other field stays editable. Timeout **30 seconds** (an image is larger than a form), then §6.3 case 4.
- **Saving**: `B01` shows `جارٍ الحفظ… / Saving…`; every field, `B02` and `B03` are disabled; further clicks send no second request. Timeout **10 seconds**, then §6.3 case 3.

### 6.2 Empty

The create form opens empty by design; that is not an empty state. The one true empty state is **no category exists**: `F05` is replaced by `C13`, `B01` is disabled, and nothing can be saved. A product without a category could not be placed in the guest's grouped list at all (G-01 §5.3).

### 6.3 Error

1. **The product could not be fetched** (edit mode): the form area shows `تعذّر تحميل المنتج / The product could not be loaded` with a "إعادة المحاولة / Try again" text button; the sidebar stays usable.
2. **Validation failed on Save**: `C08` above the buttons, plus each failing field outlined and carrying its own message from §7.7 directly beneath it. Focus moves to the first failing field in reading order. No request is sent.
3. **The save request failed or timed out**: `C12` "تعذّر الحفظ — تحقّق من الاتصال وحاول مرة أخرى. لم يُفقد ما كتبته. / Could not save — check your connection and try again. Nothing you typed was lost." Every typed value is kept exactly as typed; `B01` returns to its normal label and can be clicked again.
4. **The image upload failed, timed out, or the file was refused**: the message from §7.6 under `C07`; the form keeps whatever image it had before; every other field is untouched.
5. **A product that no longer exists** (it was removed in another tab): the same message as case 1, with the Try again button.
6. **Expired session**: A-01 per `admin-map` §4.3. `A-01-C04` warns that unsaved edits were lost.

### 6.4 Success

`B01` succeeded: A-04 closes and A-03 opens with the saved row outlined for 3 seconds and the confirmation line of A-03 §5.6. There is no success message on A-04 itself — the confirmation belongs where the manager lands.

## 7. Field rules

### 7.1 `F01` Arabic name and `F02` English name

| Rule | Value |
|---|---|
| Required | Both |
| Length | 1 to 60 characters after trimming leading and trailing spaces |
| Accepted | Any characters, including digits and punctuation. `F01` is not restricted to Arabic letters and `F02` is not restricted to Latin letters: a product is legitimately called "Pepsi" in both |
| Line breaks | Not accepted; a pasted line break becomes a single space |
| Uniqueness | Not enforced. Two products may share a name; they are different rows with different prices |
| Why 60 | The guest's card shows at most 2 lines and then an ellipsis (G-01 §5.4); 60 characters is roughly two full card lines at 14 px, so a name within the limit is usually shown whole, and G-02 always shows it whole |

### 7.2 `F03` and `F04` Descriptions

| Rule | Value |
|---|---|
| Required | Neither |
| Length | 0 to 500 characters each |
| Why 500 | G-02 renders a description up to 500 characters and cuts the rest at the last space with "…" (G-02 §5.4, decision 8). Capping the input at the same number means **no description written here is ever truncated on the guest side** |
| Accepted | Plain text, including line breaks. Single line breaks are kept and shown as line breaks on G-02 (G-02 §5.4); no other formatting is rendered anywhere, so markdown, HTML and links are stored as the literal characters and are never interpreted |
| Trimming | Leading and trailing whitespace trimmed; internal whitespace kept |

### 7.3 `F06` Price

| Rule | Value |
|---|---|
| Required | Yes |
| Accepted while typing | Western digits `0–9`, Arabic-Indic digits `٠–٩`, one `.` or one `,` |
| Normalised on blur | Arabic-Indic digits → Western; `,` → `.`; padded to exactly two decimals; a leading `.` becomes `0.` |
| Decimals | At most 2. A third decimal is a validation error, never a rounding |
| Range | **0.01 to 9999.99** inclusive. Zero, negative amounts and anything above are rejected |
| Currency | Never typed into the field. The label is static text beside it, from A-07 |
| Keyboard | Decimal numeric keyboard; `autocomplete` off |
| Stored | A decimal with exactly two places, never rounded (§5.3) |

### 7.4 `F05` Category and `F07` Stock

- `F05` is required. Its first option, `اختر فئة / Choose a category`, is not a valid selection and fails validation with its own message.
- Its options are the A-05 categories in the A-05 order. Changing a product's category moves it to the **end** of the new category's order (A-03 §7.3).
- `F07` has exactly two states. New products start on. It carries no third state, no "hidden", no "coming soon".

### 7.5 Character counters (`C05`)

One under each of `F01`, `F02`, `F03`, `F04`, reading `{used}/{max}` with Western digits (`12/60`, `340/500`). `{used}` counts characters after trimming the ends. Over the maximum, the counter takes the error style and the field cannot be saved; typing is **not** blocked at the limit, because silently swallowing keystrokes hides the problem instead of showing it.

### 7.6 Image rules and messages

| Rule | Value |
|---|---|
| Formats | JPG, PNG, WebP. Anything else is refused in the browser, before any upload |
| Maximum file size | 5 MB |
| Minimum dimensions | 500 × 500 px, checked before upload |
| Crop | Centre-cropped to 1:1 and previewed as exactly that crop |
| Upload timeout | 30 seconds |

| Condition | Arabic | English |
|---|---|---|
| Wrong format | اختر ملف JPG أو PNG أو WebP | Choose a JPG, PNG or WebP file |
| Larger than 5 MB | حجم الصورة أكبر من 5 ميجابايت | The image is larger than 5 MB |
| Smaller than 500 × 500 | الصورة صغيرة جدًا — 500 × 500 بكسل على الأقل | The image is too small — at least 500 × 500 px |
| Upload failed or timed out | تعذّر رفع الصورة — حاول مرة أخرى | The image could not be uploaded — try again |

### 7.7 Validation timing and messages — exact wording

Validation runs when `B01` is clicked. After the first failed Save attempt, each field also re-validates when it loses focus, so a corrected field clears its own message without another Save attempt. Nothing is validated while typing, except the counters in §7.5.

| Field | Condition | Arabic | English |
|---|---|---|---|
| `F01` | Empty | أدخل اسم المنتج بالعربية | Enter the product name in Arabic |
| `F01` | Over 60 characters | اسم المنتج بالعربية 60 حرفًا كحد أقصى | The Arabic product name is 60 characters at most |
| `F02` | Empty | أدخل اسم المنتج بالإنجليزية | Enter the product name in English |
| `F02` | Over 60 characters | اسم المنتج بالإنجليزية 60 حرفًا كحد أقصى | The English product name is 60 characters at most |
| `F03` | Over 500 characters | الوصف بالعربية 500 حرف كحد أقصى | The Arabic description is 500 characters at most |
| `F04` | Over 500 characters | الوصف بالإنجليزية 500 حرف كحد أقصى | The English description is 500 characters at most |
| `F05` | Nothing chosen | اختر فئة للمنتج | Choose a category for the product |
| `F06` | Empty | أدخل سعر المنتج | Enter the product price |
| `F06` | Contains anything but digits and one separator | استخدم الأرقام فقط، مثل 12.50 | Use digits only, for example 12.50 |
| `F06` | More than two decimals | السعر بخانتين عشريتين كحد أقصى، مثل 12.50 | The price has at most two decimals, for example 12.50 |

### 7.8 Unsaved-edit detection

A form has an unsaved edit when any field's current value differs from the value the form opened with, comparing trimmed values, including the stock switch and the image. Choosing an image and then removing it again, or typing a space at the end of a name, is **not** an unsaved edit. In create mode, any non-empty field, a chosen image, or a stock switch flipped off counts as an unsaved edit.

### 7.9 Sizes

Form 720 px wide; single-line fields 44 px tall; description fields 5 rows; buttons 44 px tall; every clickable element at least 32 × 32 px; image preview 160 × 160 px. Minimum text size 12 px (the counters); every message and note 13 px; field text 15 px. Browser zoom is never disabled.

## 8. Acceptance criteria

1. "+ منتج جديد / New product" opens A-04 titled "منتج جديد / New product", with every field empty, the stock switch on, no Remove button and focus in the Arabic name field.
2. Clicking a product row on A-03 opens A-04 titled "تعديل المنتج / Edit product" with every field filled from the saved product.
3. The Arabic and English name fields are shown side by side at the same time, never on tabs, in both dashboard languages.
4. Saving with an empty Arabic name shows "أدخل اسم المنتج بالعربية / Enter the product name in Arabic" beneath that field, outlines it, shows "راجع الحقول المميزة بالأسفل / Check the highlighted fields below" above the buttons, moves focus to it, and sends no request.
5. Saving with an empty English name behaves identically with its own message: both names are required.
6. A name of 61 characters shows the "60 characters at most" message for its language and blocks the save; the counter under the field is in the error style.
7. Typing past a limit is never blocked: the character is accepted and the counter shows the excess.
8. Both descriptions may be left empty and the product still saves; a description of exactly 500 characters saves, and 501 blocks the save with its message.
9. A description saved here is never truncated on G-02, because the maximum accepted equals G-02's rendering limit of 500.
10. A line break typed into a description is kept; a line break pasted into a name becomes a single space.
11. Typing `12` into the price field and leaving it shows `12.00` in the field before any save.
12. Typing `12,5` shows `12.50`; typing `١٢٫٥` shows `12.50`; the conversion happens on blur, in the field, where the manager can see it.
13. Typing `12.505` blocks the save with "السعر بخانتين عشريتين كحد أقصى، مثل 12.50 / The price has at most two decimals, for example 12.50" and never rounds it.
14. `0`, a negative amount, and `10000` each block the save with their own message from §7.7.
15. With a valid price, the preview line shows both renderings at once — `12.00 ر.س` and `SAR 12.00` — whichever language the dashboard is in, and uses the currency label from A-07.
16. The note "السعر الذي تُدخله هو ما يدفعه النزيل. لا تُضاف رسوم توصيل أو خدمة أو ضريبة على الطلب. / The price you enter is what the guest pays. No delivery, service or tax charge is added to an order." is visible under the price in every state of the form.
17. No field anywhere on A-04 accepts a fee, a tax, a discount, a cost price or a stock quantity.
18. Typing a currency symbol into the price field blocks the save with "استخدم الأرقام فقط، مثل 12.50 / Use digits only, for example 12.50".
19. The category field lists every category in the A-05 order; leaving it on "اختر فئة / Choose a category" blocks the save with its message.

22. A file that is not JPG, PNG or WebP, one larger than 5 MB, or one smaller than 500 × 500 px is refused before any upload with its own message from §7.6, and the form keeps the image it had.
23. "إزالة الصورة / Remove image" clears the image from the form only; the saved product still has its image until Save is used.
24. A product saved with no image shows the gray box with the generic icon in the preview, and the guest sees the same fallback.
25. The stock switch on A-04 changes nothing until Save is used; leaving by Cancel or Discard leaves the saved product's stock unchanged.
26. A new product's stock switch starts on.
27. Clicking Save with every field valid sends exactly one request, shows "جارٍ الحفظ… / Saving…", and on success opens A-03 with the saved row outlined for 3 seconds and the matching confirmation line.
28. A second click on Save while a save is in flight sends no second request.
29. A save that fails or times out after 10 seconds shows "تعذّر الحفظ — تحقّق من الاتصال وحاول مرة أخرى. لم يُفقد ما كتبته. / Could not save — check your connection and try again. Nothing you typed was lost.", keeps every typed value, and allows another attempt.
30. Cancel, a sidebar click or a browser back with any unsaved edit opens AM-01; with no unsaved edit it leaves immediately.
31. Typing a value and then restoring it to what it was is not an unsaved edit and does not open AM-01.
32. Editing a removed product shows "هذا المنتج مُزال من المتجر ولا يراه النزلاء. / This product is removed from the store and no guest can see it.", disables the stock switch, keeps every other field editable, and offers "استعادة / Restore".

36. A price change saved here does not change the total of any order that was already submitted.
37. Every label, note, message and counter exists in Arabic and English, and every number on the screen uses Western digits 0–9.
38. Switching the dashboard language re-renders A-04 in the other language and direction, keeps every typed value exactly as typed, and keeps both language fields visible.

## 9. Decisions settled on this screen

1. **One screen for create and edit.** Identical fields and identical rules; two screens would be two places for the same validation to drift.
2. **Both names required, both descriptions optional.** The guest's name fallback stays as a safety net but never triggers for a product edited here; the guest's "no description" state is already a complete experience (G-02 decision 9).
3. **Languages side by side, never tabbed**, so a missing English value is visible without an extra click.
4. **Name limit 60, description limit 500.** 500 is exactly G-02's rendering limit, so nothing written here is ever truncated for a guest.
5. **The price field takes an amount only**; the currency is a static affix from A-07 and its position is the guest's, not a setting.
6. **Normalisation happens on blur, visibly, before saving** — never silently at save time.
7. **The live preview shows both languages at once**, so a manager who reads only one still sees what the other guest reads.
8. **Prices are never rounded here.** The only rounding in the product is `quantity × unit price`, half up, on the guest side.
9. **No fee, tax, discount, cost or margin field**, and the reason is printed on the screen (`admin-map` §5.7).
10. **Stock is a form field on A-04 and an immediate action on A-03**, deliberately: one click where stock is the whole edit, one Save where it is one field of eight.
11. **A new product starts on sale**; a restored product starts out of stock.
12. **One image, optional, centre-cropped to a square, previewed as the crop.** No cropping tool, no gallery, no alt text in version 1.
13. **No autosave, no draft, no restore after a reload.** Unfinished products must not exist in a catalog the guest fetches whole; AM-01 is the protection.
14. **Typing is never blocked at a limit**; the counter and the message do the work, so the manager always sees what they wrote.
15. **A product cannot exist without a category**, because the guest's list is grouped by category and an uncategorised product would have nowhere to appear.
