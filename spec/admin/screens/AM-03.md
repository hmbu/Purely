Author: Thinker (Agent 1)

---

## 1. ID and name

- **ID:** AM-03
- **Name:** تفاصيل الطلب / Order details
- **Type:** Modal, no URL. Opens on top of A-06 when an order row is clicked. It does not change the active sidebar item (`admin-map` §4.2) and does not change the A-06 URL (A-06 §7.6).
- **Language:** the dashboard language. Values that are not interface copy — the order number, the room number, the guest's notes, the staff member's name, the cancellation reason — are shown exactly as stored and never translated or reformatted.

---

## 2. Purpose

Show everything one order contains and everything that happened to it, without any way to change it.

---

## 3. Entry and exit points

### 3.1 Entry

| From | Trigger | What AM-03 shows |
|---|---|---|
| A-06 | Click on an order row (`A-06-B05`) | The card at once, with `C01` built from the row's order number and `C17` in place of the body; then, when the one request of §6.1 answers, the order as stored at that moment |

That is the only entry. AM-03 is not opened from A-02, from A-03 or by a URL; it has no URL of its own, so a reload of the page closes it and shows A-06 as the URL describes it.

On open, AM-03 sends **one** request for this order's full record together with the names of the staff members its history mentions. It reads nothing else and sends nothing else.

### 3.2 Exit

| Action | Result |
|---|---|
| `B01` "إغلاق / Close" | AM-03 closes. A-06 is exactly as it was: same filters, same page, same scroll position, nothing re-fetched (A-06 §3.1). Keyboard focus returns to the row that opened AM-03 |
| A backdrop click (`S01`) | Same as `B01` |
| Esc | Same as `B01` |
| Browser back while AM-03 is open | Same as `B01`; A-06 stays open and its URL does not change |

There is no other exit. No control on AM-03 accepts, advances, cancels, edits, refunds or re-sends an order, contacts a guest, prints, or opens another order (`admin-map` §1; locked decision 5 transitions belong to the staff interface).

## 5. Content

### 5.1 Layout, top to bottom

Header: `C01` title and `C02` status on one line, `C03` under them. Body (scrolls inside the card): `C04` sent line, `C05` room, `S03` items with `C08` total, `S04` payment, `S05` notes, `S06` status history with `C16`. Footer: `B01`.

The order of the body answers the manager's questions in the order they are asked during reconciliation: **when and where** (sent time, room), **what** (items and total), **how it is paid** (payment), **what the guest asked for** (notes), **what happened** (history). The header and the footer stay in place while the body scrolls, so the order number, its status and the only control are always visible.

On open, keyboard focus is on `B01`, so Enter and Esc both close. Focus stays inside the card until it closes. A screen reader announces AM-03 as a dialog and reads `C01` and `C02` first.

### 5.2 Header, sent line and room (`C01`–`C05`)

- `C01` prints the order number exactly as stored, taken from the A-06 row, so the title is correct before the record arrives.
- `C02` prints the **current** stored status, as returned by AM-03's own request. It can therefore be newer than the status on the A-06 row, which was fetched earlier; AM-03 does not update the row, and A-06's "تحديث / Refresh" does (A-06 `B01`). This is the only case where AM-03 and A-06 can show different values for the same order, and AM-03's is the fresher one.
- `C03` is always visible: a manager who opens an order to accept it, or to push it forward, reads here, in the place the missing button would be, that this is done elsewhere.
- `C04` prints the submission moment (`createdAt`) in the hotel time zone.
- `C05` prints the room number exactly as the guest sent it: leading zeros kept, letters in the case typed, 1 to 6 characters (A-06 §5.3), 28 px bold, laid out left-to-right in both languages, never truncated. It is the largest text in the card, because the room is what a reconciliation or a complaint is about.

### 5.3 Items (`S03`) — which name is shown

This section defines the product name used for an order line anywhere in the dashboard; A-06 §7.7 refers to it for the CSV "Items" value.

1. **The name is the order's own copy, never the catalog's.** Each stored line carries the product's Arabic and English names as they were when the order was submitted (`lines[].nameAr`, `lines[].nameEn`). AM-03 prints the one for the dashboard's current language. A product renamed since, or removed from the store since, is shown under the name the guest saw and ordered; AM-03 never looks the product up in the current catalog and never marks a line as removed.
2. **Fallback.** When the stored name for the dashboard's language is empty, the stored name in the other language is printed. When both are empty, `—` is printed.
3. **Line order** is the stored order, which is the order the guest added the lines to the cart (G-04 §5.2). AM-03 never re-sorts.
4. **Quantity** is the stored whole number (1–10, G-01 §7.1), printed before `×` (U+00D7).
5. **Unit price** (line 2 of `C07`) is the stored unit price of that line, two decimals, with the currency label: `12.00 ر.س للقطعة` / `SAR 12.00 each`. It is the price the guest was charged, which can differ from today's catalog price (A-04 §5.3).
6. **Line total** = quantity × stored unit price, two decimals. No rounding occurs: the unit price has exactly two decimals and the quantity is whole, so the product has exactly two decimals.
7. **`C08` Total** is the **stored order total**, never recomputed (A-06 §7.4; G-07 "the total is never recomputed"). If the stored total ever differs from the sum of the line totals, the stored total is printed and no warning is shown: it is the amount the guest agreed to at M-01 and the amount staff collected.
8. **`C06` count** is the sum of the quantities, in the wording of G-01 §7.3: `منتج واحد` / `1 item`, `منتجان` / `2 items`, `{N} منتجات` / `{N} items` (3–10), `{N} منتجًا` / `{N} items` (11 and above) — the same value as A-06's Items column.
9. Names are printed in full, wrapping to as many lines as they need; a line is never cut with an ellipsis, because the manager may be reading it against a complaint.

### 5.4 Payment (`S04`)

- `C10` prints `بطاقة / Card` or `نقدًا / Cash`, the stored payment choice (G-04 §7.3). It is the choice the guest made, not a record of what was used at the door: version 1 records no "method actually used" (staff-map §4 decision 16).
- `C11`, cash orders only, one of two copies:

| Stored amount | Arabic | English |
|---|---|---|
| A whole number | المبلغ الذي سيدفع به: {amount} ر.س | Amount the guest will pay with: SAR {amount} |
| None | لم يحدّد النزيل المبلغ | The guest did not state an amount |

`{amount}` is the whole number the guest typed (G-04 §7.4), printed without decimals, because it is a statement about banknotes and was never a price. The label is the CSV column name of A-06 §7.7, word for word. AM-03 prints no change amount: change is worked out at the door (SM-02) and is not part of what the hotel reconciles.

### 5.5 Notes (`S05`)

- `C13` prints the stored notes exactly as the guest typed them, up to 200 characters (G-04 §7.2), line breaks kept.
- **They are untrusted text and are rendered as plain text only.** Markup, links, email addresses and phone numbers are shown as the literal characters and are never made clickable or interpreted.
- Each paragraph takes its direction from its first strong character, so an English note reads left-to-right inside the Arabic dashboard and an Arabic note right-to-left inside the English one.
- Empty or missing notes print `لا توجد ملاحظات / No notes` in 13 px gray, so an empty section is never mistaken for a failed load.

### 5.6 Status history (`S06`) and the cancellation line (`C16`)

The history lists every status the order has held, oldest first, one `C15` row each. The rows are built from the stored record in this order:

1. **New.** Always the first row: `جديد / New`, the submission time (`createdAt`), and who = `النزيل / Guest`.
2. **Each forward step reached after New**, in the order of locked decision 5 — `تم القبول وجارٍ التحضير / Accepted & preparing`, `في الطريق / On the way`, `تم التوصيل / Delivered` — up to and including the last one the order reached (the current status when it is not Cancelled; the stored `cancelledFrom` when it is). For each, the time and the staff member come from the stored `log` row for that status.
3. **Cancelled**, only when the status is Cancelled, as the last row: the time is the stored `cancelledAt`, or, when that is missing, the time of the `log` row for Cancelled.
4. **A step with no recorded time** — the order reached it, but no `log` row or cancellation time exists for it — is still listed, with `الوقت غير مسجَّل / Time not recorded` in place of the time and `—` in place of who. A step is never left out, so the history never suggests that an order skipped a status.

**Who**, in the third position of a row:

| Case | Arabic | English |
|---|---|---|
| The New row; the Cancelled row of an order the guest cancelled (`cancelledByGuest` true, or `cancelledBy` = guest) | النزيل | Guest |
| A row whose staff identity is on the staff roster | {the member's name exactly as stored on the roster} | {the same} |
| A row whose staff identity is not on the roster | موظف غير معروف | Unknown staff member |
| A Cancelled row by the hotel with no staff identity | الفندق | The hotel |

The staff member's name is printed exactly as the roster stores it, whichever language the dashboard is in (the roster holds one string per member, for example `سارة / Sara`).

**`C16` cancellation line**, only when the status is Cancelled, one of three copies:

| Case | Arabic | English |
|---|---|---|
| Cancelled by the guest | ألغاه النزيل قبل أن يقبله الفندق. | The guest cancelled it before the hotel accepted it. |
| Cancelled by the hotel, with a reason | ألغاه الفندق. السبب: {reason} | The hotel cancelled it. Reason: {reason} |
| Cancelled by the hotel, no reason | ألغاه الفندق دون سبب مسجَّل. | The hotel cancelled it with no reason recorded. |

"Before the hotel accepted it" is always true for a guest cancellation, because a guest can cancel only while the order is New (locked decision 6).

**`{reason}`** is the stored reason for the dashboard's current language (`cancelReasonAr` in the Arabic dashboard, `cancelReasonEn` in the English one), exactly as stored, never translated, plain text. When that one is empty after trimming, the other language's stored reason is printed. When both are empty, the no-reason copy is used. The reason is the text the guest read on G-06 after "ألغى الفندق هذا الطلب: / The hotel cancelled this order:" (SM-01 §7.1), at most 99 characters, and is printed whole.

### 5.7 What is deliberately not in this modal

- **No action on the order**: no accept, no status change, no cancel, no edit, no refund, no re-send, no "mark as paid" (`admin-map` §1).
- **No previous / next order controls.** The manager returns to A-06, which holds the filters and the list; two ways to walk the list would be two places to keep in step.
- **No print, no copy, no export of one order.** A-06's CSV is the way out of the dashboard.
- **No guest identity**, because an order has none (locked decision 4). No device identifier and no client order key are shown: they mean nothing to the manager.
- **No change amount** (§5.4) and **no "method actually used"**.
- **No link to the product** on A-04: a line is the order's copy, and the product may since have been renamed, repriced or removed (§5.3).
- **No auto-refresh.** The record is read once, on open (`admin-map` §1: no live operations view).

## 6. States

### 6.1 Loading

On open: the card, `C01`, `C03` and `B01` are drawn at once; `C17` fills the body; `C02` is hidden. **One** request asks for the order's full record and the roster names its history mentions. Timeout **10 seconds** (A-06 §6.1), then §6.3. `B01`, the backdrop, Esc and browser back work throughout; closing while the request is in flight discards its answer.

### 6.2 Empty

Not reachable as a whole: AM-03 always opens for one order, and every order has at least one line, a room number, a payment choice, a total and a submission time (G-04 §7.8). The parts that can be empty each have their own line: notes (`لا توجد ملاحظات / No notes`), a cash amount (`لم يحدّد النزيل المبلغ / The guest did not state an amount`), a reason (the no-reason copy of `C16`), a step time (`الوقت غير مسجَّل / Time not recorded`).

### 6.3 Error

1. **The request failed or did not answer within 10 seconds**: `C18` "تعذّر تحميل الطلب / The order could not be loaded" in place of the body, with `B02` "إعادة المحاولة / Try again". `B01` still closes.
2. **The order was not found** (it passed the 365-day retention of A-06 §7.5 between the list fetch and the click): `C18` "لم يُعثر على هذا الطلب / This order was not found", **without** `B02`, because trying again cannot find it. `B01` closes; A-06 still shows the row until its next fetch.
3. **Expired session**: A-01 per `admin-map` §4.3; the A-06 URL is the remembered address, so signing in returns to the same filtered list with AM-03 closed.

### 6.4 Success

The request answered: `C17` is replaced by the body of §5.1 within 100 ms; `C02` shows the current status; the history and, for a cancelled order, `C16` are complete.

## 7. Field rules

AM-03 has no field. The rules below govern the values it displays.

### 7.1 Values and formats

| Value | Rule |
|---|---|
| Order number | Exactly as stored: Western digits, no "#", no padding |
| Room number | Exactly as sent: 1–6 characters, leading zeros and letter case kept, left-to-right in both languages, 28 px bold, never truncated |
| Dates and times | `DD/MM/YYYY` and `HH:MM`, 24-hour, hotel time zone from A-07; the browser's time zone is never used |
| Amounts | Two decimals always; currency label from A-07 **at the time of viewing**, position per G-01 §7.2. A later label change re-labels this order's amounts and never changes one (A-07 §5.2) |
| Cash amount | Whole number as typed by the guest, no decimals, with the currency label |
| Status labels | The five labels of G-01 §5.2, verbatim, in the dashboard language |
| Product names | §5.3 |
| Notes, reason, staff names | Exactly as stored, plain text, never translated |
| Digits | Western 0–9 everywhere, in both languages |

### 7.2 Sizes

Card 640 px wide, never taller than the viewport minus 96 px; the body scrolls inside the card while the header and the footer stay. Room number 28 px; title 18 px; section headings and item lines 15 px; notes and status history 13–15 px as stated in §4. Minimum text size 13 px. `B01` 44 px tall; `B02` 36 px tall. Browser zoom is never disabled.

## 8. Acceptance criteria

1. Clicking an order row on A-06 opens AM-03 titled "الطلب رقم {n} / Order {n}" with that row's order number, and the A-06 URL and the active sidebar item do not change.
2. On open, AM-03 sends exactly one request; until it answers, the body shows gray skeleton bars with no text, while the title, "للعرض فقط — تُغيَّر حالة الطلب من واجهة الموظفين. / View only — an order's status is changed in the staff interface." and "إغلاق / Close" are visible.
3. The status pill shows the order's current stored status with one of the five canonical labels; when the status changed after A-06 was fetched, AM-03 shows the new status and the A-06 row keeps the old one until A-06 is refreshed.
4. "أُرسل في {DD/MM/YYYY} الساعة {HH:MM} / Sent on {DD/MM/YYYY} at {HH:MM}" shows the submission time in the hotel time zone from A-07.
5. A room number sent as `0305` is shown as `0305`, and one sent as `12b` as `12b`, at 28 px bold, left-to-right in both languages, never truncated.
6. Item lines appear in the stored order, each as "{qty} × {name}" with "{price} ر.س للقطعة / SAR {price} each" under it and the line total at the end side.
7. A product renamed after the order was sent appears in AM-03 under the name stored on the order, and a product removed from the store since still appears, unmarked.
8. When the order line's name for the dashboard language is empty, the name in the other language is shown; when both are empty, `—` is shown.
9. Each line total equals quantity × stored unit price with two decimals, and the Total row shows the stored order total, unchanged by any later price change on A-04.
10. The items heading shows the sum of quantities with the wording of G-01 §7.3, the same value as A-06's Items column for that order.
11. A card order shows "بطاقة / Card" and no amount line; a cash order with an amount shows "المبلغ الذي سيدفع به: {amount} ر.س / Amount the guest will pay with: SAR {amount}" with a whole number; a cash order without one shows "لم يحدّد النزيل المبلغ / The guest did not state an amount".
12. Notes appear exactly as the guest typed them, with their line breaks; a note containing `<b>x</b>` or a web address is shown as literal text and nothing in it is clickable; an order with no notes shows "لا توجد ملاحظات / No notes".
13. The first history row is always "جديد / New" with the submission time and "النزيل / Guest".
14. A delivered order that was accepted, sent and delivered by staff shows four history rows, oldest first, each with its time and the staff member's name exactly as stored on the roster.
15. A status the order reached with no recorded time is still listed, with "الوقت غير مسجَّل / Time not recorded"; no status between New and the current one is ever missing from the history.
16. A history row whose staff identity is not on the roster shows "موظف غير معروف / Unknown staff member".
17. An order the guest cancelled shows a final "ملغى / Cancelled" row with "النزيل / Guest" and the line "ألغاه النزيل قبل أن يقبله الفندق. / The guest cancelled it before the hotel accepted it."
18. An order the hotel cancelled with a reason shows "ألغاه الفندق. السبب: {reason} / The hotel cancelled it. Reason: {reason}" with the reason stored for the dashboard's language, falling back to the other language's reason when that one is empty; with no reason stored in either language it shows "ألغاه الفندق دون سبب مسجَّل. / The hotel cancelled it with no reason recorded."
19. An order cancelled from On the way lists New, Accepted & preparing, On the way and Cancelled, in that order.
20. The cancellation line is not shown for any status other than Cancelled.
21. AM-03 contains no control that changes an order: its only buttons are "إغلاق / Close" and, in the load-error state, "إعادة المحاولة / Try again".

## 9. Decisions settled on this screen

1. **Read-only, with no exception**, and the screen says so in `C03`, in the place a manager would look for the missing button (`admin-map` §1).
2. **One request on open, no refresh inside the modal.** The status can be fresher than the A-06 row; the difference is accepted and explained in §5.2 rather than solved with a second refresh control.
3. **A line's name is the order's stored copy in the dashboard language, falling back to the other language, never the current catalog name.** This is the rule A-06 §7.7 defers to for the CSV.
4. **The Total is the stored total, never the sum recomputed**, and line totals are exact products that need no rounding.
5. **The history lists every step reached, with "Time not recorded" when the record has no time**, so a missing log row never looks like a skipped status.
6. **The staff member's name is shown on each history row.** The staff interface identifies staff precisely so the hotel can say who did each irreversible act (staff-map §4 decision 2); the manager is the person who asks that question.
7. **No change amount and no "method actually used"** — the stored payment choice is what the hotel reconciles (staff-map §4 decision 16).
8. **Notes, reasons and names are untrusted plain text**, never interpreted and never made clickable, matching A-06's CSV formula guard.
9. **Dismissal follows AM-02**: Close, backdrop, Esc and browser back all close it, because AM-03 performs nothing by being open (`admin-map` §3.3 rule 5).
10. **Recorded disagreement between the staff spec and the data layer — the cancellation reason.** SM-01 §7.1 describes **one** reason string, composed in the order's language and stored "exactly as sent". `/shared/hotel-db.js` stores **two**, `cancelReasonAr` and `cancelReasonEn`, and hands the guest the one in the guest's language. AM-03 is specified against the stored shape: it shows the reason for the dashboard's language and falls back to the other (§5.6). A-06 §7.7 has a single "Cancellation reason" CSV column and does not say which of the two it writes; **flag for the owner:** the same rule as AM-03 is proposed for that column. A-06 and SM-01 were not edited.
11. **Recorded gap in the data layer — the order's language.** G-04 §7.8 sends the guest's interface language with the order and SM-01 §7.1 relies on it, but the order record described in `/shared/hotel-db.js` does not list it. AM-03 does not display the order's language, so nothing on this modal depends on it; the gap is recorded for the owner because the staff interface does depend on it.
12. **No disagreement with the map** was found for AM-03: `admin-map` §2.2 and §3.2 describe exactly this modal (read-only; items, quantities, prices, room, payment, notes, status history; closed by "إغلاق / Close", backdrop or Esc). Browser back is added as a fourth way to close, following AM-02 §3.2.
