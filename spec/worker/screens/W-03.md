# W-03 — Delivery worker sign-in (دخول المندوب)

Author: Thinker (Agent 1)
Status: **Approved** — reconciled with the built prototype (`worker/js/signin.js`, `worker/js/core.js`). Where the prototype does not build something this file requires, the passage says **Not in the prototype — build as specified.**
Governing documents: `/CLAUDE.md` locked decision 7; `/spec/worker/worker-map.md` §4 decisions 3, 4, 5, 13, 15; `/spec/staff/screens/S-03.md` — the desk sign-in this screen is built from: §5.2 (the PIN outcomes), §5.4 (arming audio), §5.6 (variant B), §7.1 (PIN rules), §7.2 (field messages); `/spec/staff/staff-map.md` §4 decisions 2, 3, 22 and Amendment A2 decisions 28, 31; `/spec/screens/G-04.md` §7.1 (digit conversion).

Conventions reused verbatim: Western digits 0–9; Arabic-Indic (٠–٩) and Extended Arabic-Indic (۰–۹) digits converted to 0–9 as typed; 44 × 44 px minimum tap areas; the 300 ms debounce; zoom never disabled; no toast.

**What differs from the desk's S-03, and why.** Three things. (1) It accepts **worker** PINs only, and says so when a supervisor PIN is typed. (2) Signing in **starts the worker's shift**: from that moment the desk can assign orders to this phone, and the screen says so before the PIN is typed. (3) It has **no queue line and no chime**: nothing is assigned to a worker who is not on shift.

---

## 1. ID and name

- **ID:** W-03
- **Name:** دخول المندوب / Delivery worker sign-in
- **Type:** Full worker screen with its own URL (prototype: `worker/index.html#/sign-in`). The worker URL on a phone with no live worker session opens it; the sign-in URL opened with a live worker session goes to W-01.
- **Variants:** **A — the phone is linked to the hotel** (the PIN field). **B — the phone is not linked** (**not in the prototype**, §5.5).
- **Language:** Arabic (RTL) on first open; the header toggle switches to English in place; saved as the worker app's language, shared with W-01 and W-02 and separate from the desk's.
- **Browser tab title:** "دخول المندوب / Delivery worker sign-in".

---

## 2. Purpose

Name the worker with a 4-digit PIN and put them on shift, so the desk can send orders to this phone.

---

## 3. Entry and exit points

### 3.1 Entry

| From | Trigger | What W-03 shows |
|---|---|---|
| The worker URL, or the sign-in URL, on a phone with no live worker session | Browser load or reload | Variant A with an empty, focused PIN field |
| WM-02 | "إنهاء الوردية / End shift" confirmed | The same |
| W-01 or W-02 (and any open sheet) | The shift was found ended — on another tab or phone (**not in the prototype:** or 12 hours passed) | The same, with no message |

Arrival from W-01 or W-02 is an in-page navigation, never a full page load, so audio stays armed.

### 3.2 Exit

| Action | Destination |
|---|---|
| The 4th digit is entered and it is a correct **worker** PIN | The shift starts, the worker session is written, and the phone goes to **W-01**, top of the list |
| The 4th digit is entered and the PIN is wrong, belongs to a supervisor, the phone is locked out, or the request failed | Stays on W-03 with the matching C05 message (§7.2) |
| Tap the language toggle (B01) | Stays; re-rendered in the other language |
| Browser back | Leaves the worker app; W-03 has no back arrow |

## 5. Content

### 5.0 What W-03 reads, writes, and never touches

W-03 **reads** the worker app's saved language and the answer to a sign-in request. It **writes**, on a correct worker PIN only: the worker's shift start in the system, and the worker session on the phone (member identity and the time of sign-in) — kept apart from the desk's session (worker-map §4 decision 3). It sends one kind of request: sign-in.

W-03 **never**: shows a list of staff names or lets anyone pick a name; shows any order content, room number or count; plays a sound; keeps the PIN after the request is sent; signs the desk in or out; offers a way to link the phone.

### 5.1 The PIN, and signing in

S-03 §5.2 steps 1–4, unchanged: the field is empty and focused on arrival; each digit fills a cell as a dot; a digit typed while the field is not focused focuses it; the 4th digit sends the request at once, clearing the typed value, disabling F01, and showing C06 "جارٍ التحقق… / Checking…"; the timeout is **15 seconds**.

**Outcomes — exactly five in the prototype, six in production:**

| Response | What W-03 does |
|---|---|
| **Correct worker PIN** — the member's role is worker | Starts the worker's shift in the system (signing in again restarts the shift's start time), writes the worker session, resets the wrong-attempt count, and replaces W-03 with **W-01** |
| **Supervisor PIN** — the PIN is correct but the member's role is supervisor | Nothing is written: no worker session, no shift, and the desk's session is untouched. F01 cleared, re-enabled, focused; C05 "هذا تطبيق المندوب. المشرف يستخدم تابلت مكتب الروم سيرفس / This is the delivery worker app. Supervisors use the room service desk tablet". **Not counted** as a wrong attempt; it resets the wrong-attempt count, as a correct PIN does |
| **Wrong PIN** | F01 cleared, re-enabled, focused; C05 "رمز الدخول غير صحيح — أعد إدخاله / Wrong PIN — enter it again" |
| **Locked out** — the 5th wrong PIN in a row, or any attempt during a lockout | F01 cleared and disabled for **60 seconds**; C05 "محاولات خاطئة كثيرة — انتظر دقيقة ثم حاول مرة أخرى / Too many wrong attempts — wait one minute, then try again"; no countdown; at 60 seconds F01 is enabled and focused and C05 hidden |
| **Failed** — not sent, dropped, no answer in 15 seconds, unreadable | F01 cleared, re-enabled, focused; C05 "تعذّر الوصول إلى النظام — تحقّق من الشبكة ثم أعد إدخال الرمز / Could not reach the system — check the network, then enter the PIN again". No shift is started |
| **Phone not linked** (**not in the prototype**) | Variant B for the rest of this page load (§5.5) |

In the prototype the wrong-attempt count is kept on the phone; in production it is the system's count, as on the desk (S-03 §5.2 step 6).

### 5.2 The shift

- The shift starts at the correct PIN and lasts until "إنهاء الوردية / End shift" is confirmed in WM-02, or until it is ended on another phone. It survives reloads and closing the tab. There is no idle lock.
- **Not in the prototype — build as specified.** It also ends **12 hours** after it started (worker-map §4 decision 4).

### 5.3 Arming audio

S-03 §5.4 rules 1–3, unchanged: any touch or key press on W-03 arms audio, typing four digits always does, and W-03 → W-01 is an in-page navigation, so W-01 starts with a working chime. W-03 itself plays nothing and shows no sound line.

### 5.4 Header

Title at the start edge, language toggle at the end edge. No back arrow, no sound control.

### 5.5 Variant B — the phone is not linked

**Not in the prototype — build as specified.** S-03 §5.6, unchanged, with C08's copy: decided from the phone on the first frame, or from an explicit "not linked" answer — never from a failed request. Header and C08 only; no request, no sound, no way forward. The link is not deleted; a reload checks again.

### 5.6 What is deliberately not on this screen

- No "Sign in" button (the 4th digit submits), no name picker, no password, no "remember me".
- No queue line, no count of orders, no chime.
- No PIN reset: C07 names the supervisor.
- No back arrow, no toast, no modal.

## 6. States

### 6.1 Loading

No loading layout on arrival. While the sign-in request is in flight: F01 disabled with four dots, C06 in the message slot, B01 still working; at most 15 seconds.

### 6.2 Empty

The empty focused field is the arrival state; no message.

### 6.3 Error

Six messages, one at a time, in C05 — the table of §7.2. Variant B is a variant, not an error state.

### 6.4 Success

A correct worker PIN: nothing drawn on W-03; the shift starts, the session is written, and W-01 is shown.

## 7. Field rules

### 7.1 F01 — PIN (رمز الدخول / PIN)

S-03 §7.1, unchanged in every row — required, exactly 4 digits, numeric keypad, Arabic-Indic digits converted, other characters not entered, leading zeros kept, paste rules, always masked, never stored, autofill and password saving suppressed — with two rows changed:

| Rule | Decision |
|---|---|
| Accepted PINs | **Worker PINs only.** Each PIN identifies exactly one staff member; a supervisor's PIN is refused on this screen with its own message (§7.2) and is not counted. |
| Lockout | After **5 consecutive wrong PINs** on this phone, sign-in is refused for **60 seconds**. A correct worker PIN or a supervisor PIN resets the count. |

### 7.2 Exact field messages (C05), one at a time

| Case | Arabic | English | Cleared when |
|---|---|---|---|
| Supervisor PIN | هذا تطبيق المندوب. المشرف يستخدم تابلت مكتب الروم سيرفس | This is the delivery worker app. Supervisors use the room service desk tablet | The next digit is typed |
| Wrong PIN | رمز الدخول غير صحيح — أعد إدخاله | Wrong PIN — enter it again | The next digit is typed |
| Locked out | محاولات خاطئة كثيرة — انتظر دقيقة ثم حاول مرة أخرى | Too many wrong attempts — wait one minute, then try again | 60 seconds after the refusal |
| Sign-in request failed | تعذّر الوصول إلى النظام — تحقّق من الشبكة ثم أعد إدخال الرمز | Could not reach the system — check the network, then enter the PIN again | The next digit is typed |
| Enter with fewer than 4 digits | رمز الدخول 4 أرقام — أكمل إدخاله | The PIN has 4 digits — finish entering it | The next digit is typed |
| Paste containing a non-digit | استخدم الأرقام فقط (0–9) | Use digits only (0–9) | The next digit is typed |

The last five are S-03 §7.2's wording, word for word.

### 7.3 Request bounds

- One sign-in request per 4th digit; timeout **15 seconds**; never retried automatically; never two in flight.
- It carries the PIN (and, in production, the phone's hotel link); nothing about a guest.

### 7.4 Tap handling, language, sizes and accessibility

- B01 responds to a single tap with the 300 ms debounce; C04 and any cell focus F01; any touch arms audio.
- Every fixed string in the worker app's saved language; typed digits and the lockout are unaffected by a switch.
- Text sizes: C01 18 px bold; C04 16 px bold; C03 16 px; C05, C06, C07 14 px. **Nothing smaller than 14 px.** B01 at least 44 × 44 px; each cell 56 × 64 px. Zoom never disabled.
- Screen reader: F01 announced with C04 and its fill state "{n} من 4 أرقام / {n} of 4 digits", never the digits; C05 and C06 announced when they appear.
- Motion: none.

## 8. Acceptance criteria

Each statement is pass/fail.

1. Opening the worker URL with no live worker session shows W-03 with F01 empty and focused; with a live worker session it shows W-01.
2. The title reads "دخول المندوب / Delivery worker sign-in"; C03 "أدخل رمزك لتبدأ ورديتك وتصلك الطلبات المحوّلة لك / Enter your PIN to start your shift and receive the orders assigned to you" is above the field; C07 reads "نسيت رمزك؟ اطلبه من مشرف الروم سيرفس / Forgot your PIN? Ask the room service supervisor".
3. W-03 has no back arrow, no sound control, no "Sign in" button, no queue line, and plays no sound.
4. Entering the 4th digit sends exactly one request, disables F01 and shows "جارٍ التحقق… / Checking…".
5. A correct worker PIN (2222 Khalid or 3333 Ahmed in the prototype) starts that worker's shift — the desk's SM-03 then lists them as "في الوردية / On shift" at once — writes the worker session, and opens W-01.
6. A correct worker PIN never signs the desk in or out: a desk session in the same browser is unchanged.
7. A supervisor PIN (1111 in the prototype) starts no shift, writes no worker session, leaves the desk session unchanged, and shows "هذا تطبيق المندوب. المشرف يستخدم تابلت مكتب الروم سيرفس / This is the delivery worker app. Supervisors use the room service desk tablet".
8. Five consecutive wrong PINs disable F01 for 60 seconds with the lockout message and no countdown; a supervisor PIN is not counted, and it resets the count.
9. A wrong PIN, a failed request and a short Enter show the messages of §7.2 exactly; a paste with a non-digit enters nothing and shows "استخدم الأرقام فقط (0–9) / Use digits only (0–9)".
10. Signing in again restarts the shift's start time shown on W-01-C01.
11. When the shift is ended on another tab or phone, the phone shows W-03.
12. The PIN is not in device storage or in the page after the request is sent, and the browser never offers to save it.
13. B01 switches every string and the direction in place and changes the worker app's language only.
14. No text is smaller than 14 px; every tappable element is at least 44 × 44 px; a screen reader never reads a PIN digit.
15. **Not in the prototype — build as specified.** On a phone with no hotel link, W-03 shows variant B on its first frame with C08's three lines word for word as on S-03 and sends nothing; the shift ends 12 hours after sign-in.

## 9. Decisions settled on this screen

1. **Worker PINs only; a supervisor PIN is named and refused, and is not counted as a wrong attempt** (§5.1, §7.1): the PIN is a real one, so it reveals nothing a wrong PIN would not, and the supervisor is told which device to use.
2. **Signing in is starting the shift, and the screen says so before the PIN is typed** (C03).
3. **No queue line and no chime on W-03**, unlike the desk's S-03: nothing is assigned to an off-shift worker.
4. **Signing in again restarts the shift's start time** (§5.1), as built.
5. **Variant B is S-03's, word for word** (§5.5), not in the prototype.
