---

## 1. ID and name

- **ID:** G-02
- **Name:** تفاصيل المنتج / Product details
- **Type:** Full guest screen, one product at a time. It exists because the card on G-01 cannot hold a description or a large image (map §4 decision 5). It has its own URL (the store URL plus the product identifier), so the browser back gesture and a page reload behave as defined in §3.
- **Language:** the current interface language (Arabic RTL by default, English LTR if the guest switched on G-01). G-02 has no language toggle (map §2.3 rule 6; §4 decision 12).

---

## 2. Purpose

Show one product in full — large image, complete name, description, price, and availability — and let the guest add it or change its quantity without leaving the screen.

| G-03 Cart | Back arrow / browser back, when G-03 was opened from G-02's cart bar | Same scroll position the guest left. | Browser reload on G-02, or the G-02 URL opened directly (typed, bookmarked, restored tab) | Page load | Loading state (§6.1): the catalog is fetched exactly as on a G-01 first open (same request, same 10-second limit), the saved language and saved cart are read from the device first. G-02 is a history entry: the browser back gesture/button does exactly what the back arrow does (map §2.3 rule 1).

### 3.2 Exit (where each action leads)

| Action on G-02 | Destination |
|---|---|
| Tap the back arrow (B01) or browser back | G-01 at the scroll position the guest left, without a catalog fetch (G-01 §3.1). If G-02 was opened by reload/direct URL, G-01 at the top of the list. The card of this product on G-01 shows the quantity now in the device cart |
| Tap "Add", "+", "−" | Stays on G-02; the cart is updated in place; the action row and the floating cart bar update |
| Tap the floating cart bar (B05) | G-03 Cart. G-03 records that it was opened from G-02, so its back arrow returns here |
| Tap "Back to store" (B06, error state only) | G-01, same rule as the back arrow (remembered scroll position, or top of the list after a reload/direct URL) |
| Catalog request fails on a reload/direct URL open | G-08 Store unavailable replaces G-02 entirely. "Retry" on G-08 leads to G-01, not back to G-02 (map §2.2) |

Nothing on G-02 leads to G-07, G-06, or a language switch; those live on G-01.

## 5. Content

### 5.1 Header (S01)

Layout, in visual order for Arabic (RTL): [B01 back arrow] … [C01 title] … (empty end edge). In English the back arrow sits at the left edge and points left; the title stays centered. The end edge of the header is deliberately empty: no "My orders" button, no language toggle, no cart icon (those are on G-01; the cart is reached from the floating bar).

- B01 is the only control in the header. Its icon is a chevron; there is no "Back" text next to it. The accessible name is "رجوع" / "Back".
- C01 is the header title, 18 px bold, one line, centered, maximum width 270 px at a 390 px viewport (60 px reserved at each edge: the start reserve holds B01's 44 px plus a 16 px gap, the end reserve mirrors it so the title is centered on the viewport, not on the leftover space).
  - **Success state:** C01 shows the **product name** in the current language. A name that does not fit on one line within 270 px is cut and ends with an ellipsis "…" (the ellipsis sits at the end of the line in the reading direction: left end in Arabic, right end in English). It never wraps, so the header height (56 px) never changes with the length of the name. This is a second, truncatable instance of the name; the full name stays in the body as C03, wrapping and never truncated, so G-01 §7.5's promise "the full name is always visible on G-02" still holds. The header carries the name so that a guest scrolled to the bottom of a long description can always see which product they are on.
  - **Loading and error states:** C01 shows the fixed fallback copy "تفاصيل المنتج" / "Product details" — in the loading state there is no name to show yet; in the error state there is no product.
  - Language fallback: if the English name is missing, the Arabic name is shown in the English interface (§7.7), exactly as for C03.
- The header is the only fixed element at the top and the floating cart bar the only fixed element at the bottom (map §1.3). Nothing else on G-02 is sticky.

### 5.2 Image (C02)

- One image per product: the same catalog image the card on G-01 uses (the catalog provides one image URL per product; there is no gallery, no second image, no zoom).
- Area: full viewport width, 4:3 aspect ratio (390 × 292 px at a 390 px viewport; scales with the viewport width). Light gray background across the whole area.
- Fit: the image is scaled so that it fits entirely inside the area (no cropping) and is centered; a square catalog photo therefore shows with gray bands on the left and right. This is chosen so that no part of the product is ever cut off, which the 1:1 card crop on G-01 does not guarantee for the larger view.
- No image, or image fails to load: the gray area stays at the same size and shows a centered 64 px generic product icon (the same icon family as G-01 §5.4 item 1, at twice the size). No text such as "No image" is shown.
- Out of stock: the whole area (photo or placeholder) is shown at 50 % opacity, the same treatment as the card on G-01.
- The image is not tappable: a tap on it does nothing (no zoom, no full-screen view, no navigation).
- The image scrolls with the page; it is not fixed or parallax.

### 5.3 Name, price, and action row (C03, C04, S03)

Top to bottom under the image, all within the 358 px content width:

1. **Name (C03)** — 20 px bold, 16 px below the image. Shown in full: it wraps onto as many lines as it needs and is never truncated (G-01 §7.5 promises "the full name is always visible on G-02"). Language fallback: if the English name is missing, the Arabic name is shown in the English interface.
2. **Price (C04)** — 18 px bold, 8 px below the name. Arabic "12.00 ر.س", English "SAR 12.00" (G-01 §7.2). No strikethrough, no discount, no "per unit" text, no tax line in version 1.
3. **Action row (S03)** — 48 px tall, 16 px below the price. Exactly one of:
   - B02 "أضف / Add", full content width — when the product is available and its cart quantity is 0.
   - Stepper [B03 −] [C05 quantity] [B04 +], 160 px wide, centered — when the product is available and its cart quantity is 1–10. C06 "الحد الأقصى 10 / Max 10" (14 px, regular weight, one line, 4 px below the row) appears centered under the stepper when the quantity is 10.
   - C07 badge, full content width — when the session catalog copy marks the product as out of stock (G-01 §5.7). No stepper is shown even if the cart already contains this product; that cart line is handled on G-03 (map §4 decision 9), and the floating cart bar still counts it. Badge text:
     - Cart holds none of this product: "غير متوفر" / "Out of stock".
     - Cart holds N of this product: "غير متوفر — في سلتك {N}" / "Out of stock — {N} in your cart" (example: "غير متوفر — في سلتك 2" / "Out of stock — 2 in your cart"). In this case C08 "لإزالته من السلة افتح السلة" / "To remove it, open the cart" (14 px, regular weight, one line, 4 px below the row) is shown under the badge, because on G-02 there is no other hint about where the line can be removed.
4. **Active-order line (C13)** — one sentence of plain text, 14 px, regular weight, centered on the 358 px content width, wrapping onto at most two lines, never truncated; no icon, no border, no fill, no color change, no animation; not tappable. It sits 8 px below the action row, or 8 px below C06 / C08 when one of those is shown, so that it is on screen at the same time as the button it is about (the image, name, price, and action row fit within the first 480 px of the viewport, see below). Copy, identical word for word to G-01 §5.2 line 2 in both languages:
   - Arabic: "أي منتج تضيفه الآن سيُرسل كطلب جديد منفصل"
   - English: "Anything you add now is sent as a new, separate order"

   Shown whenever the device holds at least one order whose last known saved status is New, Accepted & preparing, or On the way — the same condition under which G-01 shows its banner, evaluated from the same saved data (§5.7). It is shown whatever the order's status among those three, whether or not the cart has items, and whichever of the three action-row forms is showing (Add, stepper, or badge). It is a statement of fact, not a warning state: its text never changes, it does not react to a tap on Add / + / −, and it never disables, hides, or gates B02, B03, or B04. When the device holds no such order it is simply absent (no empty space beyond the normal 24 px gap to S04). It is hidden in the loading and error states.

There is no separate "متوفر / Available" label on the screen: availability is expressed only by which of the three action-row forms is shown. An available product shows Add or the stepper; an unavailable one shows the badge.

Why the action row is here, above the description, and not in a sticky bottom bar: with the 4:3 image, the name, price, and action row all fit within the first 480 px of the viewport, so the guest sees the Add button without scrolling on every phone this spec targets, and the floating cart bar remains the only fixed element at the bottom (map §1.3). The action row scrolls away when the guest reads a long description; there is no second, sticky copy of it, and none is added in this revision. A guest scrolled into the description sees which product they are on from the header title C01 (§5.1) and reaches Add again with an ordinary scroll upward; the fixed cart bar offers a way forward at all times.

### 5.4 Description (S04, C09, C10)

- S04 sits 24 px below C13 when C13 is shown; otherwise 24 px below the action row (or below C06/C08 when one of those is shown). It scrolls with the page as part of the body; nothing on the screen scrolls independently.
- C09 is the fixed title "الوصف" / "Description", 14 px bold.
- C10 is the description text from the catalog in the current language, 14 px, line height 20 px, plain text. Single line breaks in the catalog text are kept as line breaks; no other formatting (bold, links, lists) is rendered.
- Length: up to 500 characters are rendered (§7.4). If the catalog text is longer, the text is cut at the last space before the 500th character and "…" is appended. There is no "Read more" control in version 1.
- Language fallback: if the English description is missing and the Arabic exists, the Arabic text is shown in the English interface. If neither exists, S04 is hidden entirely (no title, no "No description" text); the body then ends after the action row (plus C06/C08 when shown) and its 96 px bottom padding.

### 5.5 Floating cart bar (S05 / B05)

Identical to G-01 §5.5 in size, position, content, and wording:

- Visible only when the cart has at least one line (any product with quantity ≥ 1, including out-of-stock lines still in the cart, including a line for this very product while C07 is shown).
- Start side: item count per G-01 §7.3, 14 px. Center: "عرض السلة" / "View cart", 16 px bold. End side: total per G-01 §7.2, 16 px bold.
- Updates within 100 ms of any tap on B02, B03, or B04.
- Tapping it opens G-03; G-03 opened from here returns to G-02 on its back arrow (map §2.2).

### 5.6 What is deliberately not on this screen

- No language toggle and no "My orders" button (map §2.3 rule 6; §4 decision 12): the guest goes back to G-01 for both.
- No active-order banner (it lives on G-01 only, G-01 §5.2; map §1.3). The only order-related content on G-02 is the one sentence C13, and it is a sentence and nothing else. Explicitly excluded, exactly as on G-01: no order number, no status label, no "متابعة الطلب › / Track order ›" link, no chevron, nothing tappable about the order, no banner styling; no path from G-02 to G-06.
- No disabling or gating of Add / + / − because of an active order: B02, B03, and B04 behave exactly as they do with no active order.
- No modal, no confirmation, no "are you sure this is a new order?" step before or after Add / + / −.
- No order-editing path, no "add to my existing order", no cancel control. Editing a submitted order stays out of version 1: cancel while New (M-02) then reorder (G-06 → G-03), told on G-06.
- No per-product notes field: notes are order-level on G-04 (map §4 decision 4).
- No quantity typing: the quantity changes only with "+" and "−" (same as G-01).
- No image zoom, gallery, or second image.
- No "Available" label, no stock count ("only 3 left"), no related products, no share or favorite control, no ratings.
- No toast (the only toast in version 1 is on G-03 after Reorder, map §1.3). Feedback for "Add" is the stepper appearing and the cart bar appearing or updating.
- No "Read more" on the description.
- No stock re-check request and no order-status request: G-02 never calls the server on its own. It reads stock from the session catalog copy (G-01 §5.7) and the active-order state from the device (§5.7); stock is re-checked on G-03 and at submission (M-04), and order status is refreshed on G-01 (once per load) and G-06.

### 5.7 Data source and stock marks

- Arriving from G-01 or returning from G-03, G-02 renders from the device's session catalog copy (G-01 §5.7) and the device cart. No request is sent.
- Arriving by reload or direct URL, G-02 triggers the same single catalog fetch that G-01 performs on a first open, and the response becomes the new session catalog copy for the rest of the session (so a later back to G-01 does not fetch again).
- Stock marks flow one way: G-02 reads them, it never writes them. A mark written by G-03 or M-04 during the session is shown on G-02 as C07 on the next render (for example, G-02 → G-03 → back to G-02).
- "Out of stock" and "removed from the catalog" are different situations and produce different screens: a product that is in the session catalog copy but marked out of stock shows the success state with C07; a product that is not in the session catalog copy at all shows the error state (§6.3 case 1). The second situation cannot arise on the path from G-01 (the card was rendered from the same copy), only on a reload/direct URL.
- **Active-order state for C13.** C13 reads the **last known active-order state already saved on the device**: the orders stored per map §2.3 rule 5 (written on submission by G-05, their last known status updated by G-01's once-per-load status fetch — G-01 §5.2, map §2.3 rule 5 — and by G-06's live fetch). C13 is shown when at least one saved order has last known status New, Accepted & preparing, or On the way. **G-02 sends no status request of any kind**: not on arrival from G-01, not on return from G-03, not on reload/direct URL, and not on Add / + / −. On the reload/direct-URL path C13 uses the saved value with no fetch and no error text. If the device has never stored an order, or every stored order is Delivered or Cancelled, the line does not appear. G-02 reads this state and never writes it.

### 5.8 Decisions settled on this screen (not previously settled by CLAUDE.md, the map, or G-01)

1. **The header title is the product name in the success state**, one line, 18 px bold, ellipsis when it does not fit within 270 px (at 390 px), header height fixed at 56 px; the fixed copy "تفاصيل المنتج / Product details" survives only as the loading and error fallback. (The original decision — a fixed generic title, never the product name — was overturned by `/spec/reviews/G-02.md` §3 D1 / §4.2 F6 and no longer applies anywhere in this file.)
2. **Image area: full viewport width, 4:3, "contain" fit, never cropped**, light gray bands where the image does not fill the area.
3. **The image is not tappable**: no zoom, no gallery, no full-screen view. Page pinch-zoom is the only enlargement.
4. **The action row sits inline under the price and is not sticky.** G-02 keeps exactly one fixed element at the top (the header) and one at the bottom (the floating cart bar). A guest scrolled into the description identifies the product from the header and reaches Add by scrolling up.
5. **Stepper visible size 48 × 48 px, group 160 px centered**; tap area equals the visible shape. G-01 uses 40 × 40 px with extended tap areas; the behavior, cap, lock, and wording are identical.
6. **"Add" is a full-content-width pill (358 × 48 px)**, the largest target on the screen.
7. **Helper C08 "لإزالته من السلة افتح السلة / To remove it, open the cart"** appears under the badge when the cart holds the out-of-stock product; removal itself stays on G-03 (map §4 decision 9). G-02 has no remove control.
8. **The description is rendered up to 500 characters**, cut at the last space before the 500th character, "…" appended, no "Read more".
9. **With no description in either language, S04 is hidden entirely** — no title, no placeholder.
10. **G-02 has no empty state, by rule** (§6.2).
11. **Error state "المنتج غير متوفر / Product not available" + "العودة إلى المتجر / Back to store"**, reachable only by reload / direct URL; the cart bar is hidden there and the device cart is untouched.
12. **G-02 has its own URL.** A reload or direct open sends the same single catalog request as a G-01 first open, with the same 10-second limit; failure goes to G-08 and "Retry" on G-08 leads to G-01.
13. **G-02 sends no active-order status request and no stock request, ever.** Stock comes from the session catalog copy; order state comes from the device.
14. **After a reload / direct-URL open, back leads to G-01 at the top of the list** (no remembered scroll position).
15. **No "متوفر / Available" label**: availability is expressed only by which action-row form is shown.
16. **Active-order line C13**: one non-tappable sentence, identical copy to G-01's banner line 2, 14 px, placed 8 px under the action row (or under C06 / C08), shown from the device's saved order state alone in the success state only. It is not a banner: no order number, no status, no link, no gating, no modal, no editing path. The sentence on G-01 and on G-02 is always edited together.
17. **Minimum text size on G-02 is 14 px** (C06, C08, C10, C12 line 2, C13, the cart-bar count). Nothing on this screen is rendered smaller.
18. **Header title width is 270 px at a 390 px viewport** (60 px reserved at each edge), so the title is centered on the viewport and never collides with the back arrow.

## 6. States

### 6.1 Loading

Triggered by: browser reload on G-02, or the G-02 URL opened directly. **Never** triggered by arriving from G-01 or from G-03, which render from the session catalog copy within 100 ms and show no skeleton.

On screen:
- S01 header with B01 fully functional (a tap during loading goes to G-01, which then performs its own load) and C01 showing the fallback title "تفاصيل المنتج / Product details" (there is no name to show yet).
- C13 hidden (it belongs to the success state only).
- C11 skeleton in the body: gray image block 390 × 292 px, name bar 240 × 20 px, price bar 100 × 18 px, action-row bar 358 × 48 px, three description bars 358 × 14 px; pulsing between 100 % and 60 % opacity every 1.5 seconds; no text.
- S05 cart bar hidden.

Rules:
- The catalog request is the same request G-01 sends on a first open, with the same 10-second limit (G-01 §6.1). The active-order status request G-01 sends is **not** sent by G-02; it is sent when the guest reaches G-01. Whether C13 appears once the success state is painted is decided from the order state already saved on the device (§5.7).
- On response: product found → success state (§6.4) scrolled to the top; product not found → error state (§6.3 case 1); connection error, server error, or timeout → G-08 (connection/server variant) replaces G-02; URL not a valid store link → G-08 (invalid-link variant).
- The loading state never lasts longer than 10 seconds.

### 6.2 Empty

Not reachable, by rule: G-02 always shows exactly one product, and every piece of optional content has its own fallback rather than an empty screen — no image → the gray placeholder with the icon (§5.2); no description → S04 hidden (§5.4); no English name → Arabic name (§5.3); no active order on the device → C13 absent (§5.3 item 4). A product that cannot be shown at all is the error state (§6.3), never an empty state. There is no empty-state copy, element, or wireframe for G-02.

### 6.3 Error

There are three error situations. None of them shows a toast.

1. **Product not available** — the product identifier in the URL is not in the catalog that was just fetched (product removed from the catalog, or a wrong identifier in the URL). Reachable only after a reload/direct URL load (§5.7). On screen:
   - S01 header with B01, and C01 showing the fallback title "تفاصيل المنتج / Product details" (there is no product whose name could be shown).
   - C13 hidden, even if the device holds an active order: the error state offers one action and no Add control, so the sentence has nothing to refer to.
   - C12, centered in the body area:
     - Line 1 (18 px, bold): "المنتج غير متوفر" / "Product not available"
     - Line 2 (14 px): "ربما تمت إزالته من المتجر" / "It may have been removed from the store"
   - B06 "العودة إلى المتجر / Back to store" 24 px under the text.
   - S05 cart bar hidden, even if the cart has lines: the error screen offers one action, and the cart is one tap away on G-01. The device cart is not modified by this state; if it holds a line for the removed product, G-03 handles it through its own stock re-check.
   - B01 and browser back do the same as B06.
2. **Catalog cannot be loaded** on a reload/direct URL load (no connection, server error, timeout, invalid link): G-02 is not shown; G-08 replaces it (map §4 decision 13). All copy for that case lives in the G-08 file.
3. **Product image fails to load**: the image area shows the gray placeholder with the 64 px icon (§5.2). No error text. Everything else on the screen stays fully functional.

There is no typed input on G-02, so there are no field error messages on this screen.

### 6.4 Success

The product is in the session catalog copy.

On screen:
- S01 header with B01 and C01 showing the product name in the current language (one line, ellipsis when it does not fit, §5.1).
- S02 body scrolled to the top (or to the remembered position when returning from G-03), containing: C02 image (or placeholder), C03 full name, C04 price, S03 action row in the form matching the device cart and the session catalog copy (§5.3 item 3), C06 or C08 when their conditions hold, C13 when the device holds an order whose last known status is New / Accepted & preparing / On the way (§5.3 item 4, §5.7), S04 description when a description exists.
- S05 cart bar shown if the device cart has at least one line, with the correct count and total.

Add/stepper success feedback: after a tap on B02, B03, or B04, the action row and the cart bar update within 100 ms. Nothing else moves, nothing scrolls, no toast, no navigation. When C13 is visible it stays exactly as it was: same text, same position, nothing disabled, no modal, no confirmation. A product taken to quantity 0 with "−" shows "Add" again and stays on G-02.

## 7. Field rules

Nothing is typed on this screen. The rules below govern the bounded values G-02 displays or changes.

### 7.1 Quantity for this product (changed with B03 / B04)

Identical to G-01 §7.1; restated so the technical team never has to guess:

- Type: whole number.
- Minimum in the cart: 1. Tapping "−" at 1 removes the line (the action row returns to "Add"). There is no "remove" confirmation.
- Maximum: **10**. At 10 the "+" button is disabled (50 % opacity, tap does nothing) and C06 "الحد الأقصى 10 / Max 10" is shown under the stepper. Nothing else happens at the maximum: no toast, no modal.
- The quantity shown is always the quantity stored in the device cart for this product, so it matches what G-01's card and G-03 show. If the guest arrives with the product already at 10 (added on G-01), G-02 opens with the stepper at 10, "+" disabled, and C06 visible.
- Adding is a device-side action only; G-02 does not call the server on "Add", "+", or "−".
- Tap lock: after any tap on B02, B03, or B04, the action row ignores further taps for **300 ms** while it re-renders (G-01 §7.1). A rapid double-tap on "أضف / Add" produces quantity 1, never 2; a rapid double-tap on "+" or "−" changes the quantity by exactly 1. The lock applies to the action row only: B01 and B05 respond immediately during those 300 ms.
- Out of stock: no quantity can be changed on G-02 (C07 replaces the row). The existing cart line, if any, is left untouched and is handled on G-03.

### 7.2 Price and total

- Unit price: from the catalog, exactly two decimals, currency per G-01 §7.2.
- Cart bar total: sum over all cart lines of (quantity × unit price as currently loaded in the catalog), rounded to two decimals, half up (G-01 §7.2). Lines for out-of-stock products are included until the guest removes them on G-03.
- Digits: Western 0–9 in both languages.

### 7.3 Item count on the cart bar

Exactly the wording table of G-01 §7.3 (sum of quantities; "منتج واحد / 1 item", "منتجان / 2 items", "{N} منتجات / {N} items" for 3–10, "{N} منتجًا / {N} items" for 11 and above).

### 7.4 Text limits

- Header title (C01): one line, never wraps. Success state: the product name, cut with an ellipsis "…" when it exceeds 270 px (at a 390 px viewport). Loading and error states: the fixed fallback copy "تفاصيل المنتج / Product details", which fits in both languages.
- Product name (C03): shown in full, wraps, no truncation, no maximum imposed by this screen.
- Active-order line (C13): fixed copy, 14 px, wraps onto a maximum of two lines within 358 px, never truncated (it does fit: the longer of the two languages, "Anything you add now is sent as a new, separate order", wraps to two lines at 14 px).
- Price (C04): one line.
- Description (C10): maximum **500 characters** rendered. Beyond 500, the text is cut at the last space before the 500th character and "…" is appended. Single line breaks are kept; consecutive blank lines are collapsed to one. No "Read more".
- Badge (C07) and helpers (C06, C08): one line each; C07 with the cart suffix must fit on one line at 16 px within 358 px in both languages (it does: the longest form is "Out of stock — 10 in your cart").

### 7.5 Sizes and touch targets

- Every tappable element has a tap area of at least 44 × 44 px: B01 (44 × 44), B02 (358 × 48), B03 and B04 (48 × 48), B05 (358 × 56), B06 (200 × 44). None of them needs an extended area because every visible shape already meets the minimum; the rule of G-01 §7.6 still applies if any visible size is later reduced.
- B03 and B04 tap areas never overlap each other; C05 between them is not tappable.
- **Minimum text size on this screen: 14 px.** Nothing on G-02 is rendered smaller (the 10 px icon label that G-01 §7.6 allows under its "My orders" button does not exist here). Sizes: C06, C08, C13, C10, C12 line 2, and the cart-bar item count are 14 px regular; C09 is 14 px bold; C07 is 16 px; the cart-bar label and total are 16 px bold; C04 is 18 px bold; C01 (product name or fallback) and C12 line 1 are 18 px bold; C03 and C05 are 20 px bold.
- Browser zoom and text scaling are never disabled (same rule as G-01 §7.6): no `user-scalable=no`, no maximum scale, no rule blocking the browser's text-size setting.

### 7.6 Image

- Area: full viewport width, 4:3 aspect ratio (292 px tall at 390 px wide).
- Fit: contain (whole image visible, centered, light gray bands where it does not fill the area). Never cropped, never stretched.
- Fallback: centered 64 px generic product icon on the gray area, for both "no image in the catalog" and "image failed to load". No text.
- Out of stock: 50 % opacity on the whole area.

### 7.7 Language

- G-02 uses the language currently saved on the device (Arabic if none is saved). No toggle on this screen.
- Fallbacks when an English value is missing: name → Arabic name (in both C03 and the header title C01); description → Arabic description; category is not shown on G-02, so no category fallback is needed. The fallback title of C01 and the copy of C13 are fixed strings in each language and need no fallback.
- Direction follows the language: RTL in Arabic (back arrow at the right edge, "−" still at the left of the stepper), LTR in English.
